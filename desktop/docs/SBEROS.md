# Адаптация Desktop под SberOS UI Kit

Состояние: [DESKTOP-001](../../docs/tasks/DESKTOP-001.md), сценарии `09-02`,
`09-01`, `09-06`. Сохраняются лицензии ресурсов SberOS-компонентов. Документ
описывает адаптер палитры и его пользовательскую установку; предыдущие
установки и проверки зафиксированы в [отчётах](checks/2026-10-22/README.md).

## Первый этап

Отдельный `tools/gen_sber_theme.py` генерирует `SberOSLight.colors`,
`SberOSDark.colors`, CSS для GTK 3/4 в обеих темах и `manifest.json`.
Требуется только Python 3, дополнительные Python-пакеты не нужны.
Генератор не вызывает D-Bus, установщики, команды KDE, переключатели или сервисы.

Из корня рабочей области:

```sh
python3 desktop/tools/gen_sber_theme.py --output /tmp/sber-desktop-check
python3 desktop/tests/test_sber_theme.py -v
# Необязательная проверка установленными парсерами GTK, каждый в своём процессе:
timeout 15s python3 desktop/tests/check_gtk_css.py 3 /tmp/sber-desktop-check
timeout 15s python3 desktop/tests/check_gtk_css.py 4 /tmp/sber-desktop-check
```

`--resources PATH` задаёт каталог ресурсов другой проверяемой копии UI Kit;
по умолчанию используется `ui-kit/resources` этой рабочей области.
`--output` обязателен; генератор перезаписывает только свои семь файлов в нём.
Для проверки используйте отдельный каталог, а не пользовательский профиль.
Одинаковые ресурсы дают побайтно одинаковый результат; время и абсолютные пути
в файлы не записываются. Манифест содержит SHA-256 прочитанных источников,
карту семантических ролей и выбранный цвет текста на акценте.

## Контракт адаптера

Потребитель QML продолжает использовать [API UI Kit](../../ui-kit/docs/API.md).
Адаптер конфигурационных файлов читает `theme/sdds_os.json` и ссылки вида
`[os.osGreen.600]` из `theme/colors/`. Конвертация проверена по
`ui-kit/theme/theme_functions.h`: исходные hex-строки — `RRGGBB`/`RRGGBBAA`,
во время загрузки UI Kit переводит их в Qt `AARRGGBB`. Генератор читает исходный
формат и не применяет к нему правила формата Qt.

| Роль рабочего окружения | Токен `Theme.Palette` |
| --- | --- |
| Окно, заголовок | `Background.Default.Primary` |
| Рабочая область, поле ввода | `Background.Default.Secondary` |
| Боковая панель, карточка, popup | `Background.Default.Tertiary` |
| Кнопка / hover / pressed | `Surface.Default.TransparentSecondary` / `TransparentSecondaryHover` / `TransparentSecondaryActive` |
| Выделение / hover / pressed | `Surface.Default.Accent` / `AccentHover` / `AccentActive` |
| Текст / неактивный / disabled | `Text.Default.Primary` / `Secondary` / `Tertiary` |
| Ссылка | `Text.Default.Info` |
| Успех / предупреждение / ошибка | `Text.Default.Positive` / `Warning` / `Negative` |
| Граница / фокус | `Outline.Default.SolidSecondary` / `Accent` |
| Текст выделения | `Text.OnLight.Primary` либо `Text.OnDark.Primary` |

Названия `TransparentSecondary` не означают разрешения просвечивания рабочего
стола: в текущем UI Kit их значения непрозрачны. При появлении альфа-канала
у выбранного фона генерация завершается с ошибкой до записи результатов.
Полупрозрачный текст смешивается с конкретной поверхностью, RGB округляется
до ближайшего целого. Текст на акценте выбирается из двух токенов по наибольшему
минимальному контрасту на normal/hover/pressed. Это адаптация для ограниченных
палитр KDE/GTK, а не обещание достижения заданного порога доступности.

KDE получает отдельные группы Window/View/Button/Selection/Tooltip/Header и WM;
все экспортированные цвета — непрозрачные RGB. GTK получает именованные цвета
и общий для GTK 3/4 набор правил normal/hover/pressed/disabled/selection/focus.
Это базовый слой поверх темы toolkit: он не заменяет весь набор состояний,
виджетов и клиентских декораций. Радиусы, шрифты, размеры, тени, иконки,
параметры disabled KDE и глобальные эффекты пока не меняются. Это сохраняет
пользовательское масштабирование текста; соответствие типографике UI Kit
ещё предстоит реализовать и проверить.

KDE `.colors` палитра задаёт системные цвета Plasma и совместимых KDE-приложений;
она не дублирует Kvantum. Kvantum отдельно рисует Qt Widgets. Скрипт генерации
создаёт обе палитры в каталоге вывода; их проверенные копии лежат в
`color_scheme/SberOSLight.colors` и `color_scheme/SberOSDark.colors`.

## Карта исходного комплекта и потребителей

| Область | Текущее назначение / потребители | Действие |
| --- | --- | --- |
| `tools/gen_sber_theme.py`, `tests/` | Изолированная генерация и проверка палитр из UI Kit | Поддерживать в корневом `desktop/`; генератор не применяет системные настройки |
| `color_scheme/SberOSLight.colors`, `SberOSDark.colors` | Проверенные системные KDE color schemes, созданные из UI Kit | Обновлять генератором; устанавливать в пользовательский каталог `color-schemes/` |
| `Kvantum/SberOS/` | Тема Qt Widgets для светлого и тёмного режима | Поддерживать отдельно от GTK и QML |
| `install.sh` | Пользовательская установка KDE-палитр, GTK CSS и темы Kvantum с резервированием заменяемых файлов | Использовать для установки/проверки/отката; не переключает системный widget style |
| `lock/sberos.lock/` | Экран блокировки Plasma | Сохранять системную аутентификацию и пользовательские обои |
| `sddm/` | Экран входа до запуска сессии | Устанавливать отдельным системным установщиком; не менять PAM или автологин |
| Бывший `shell/desktop/` | Sirca Glass Desktop: GTK/KDE appliers, `glass-mode`, смена цвета папок, старый lock screen и OSD | Удалён по решению пользователя 2026-10-26 вместе с его установочными пунктами и зависимостями оболочки. Дальнейшая desktop-работа ведётся только в корневом `desktop/` |
| `third_party/adw-gtk3/`, Glass assets и лицензии внутри бывшего каталога | Ресурсы старого Glass-пути | Удалены вместе с каталогом; SberOS-адаптер не использует их |

Darkly и связанная с ним Glass-декорация удалены из Sirca и зеркала
`refs/sirca-shell`; Qt-приложения используют выбранный пользователем системный
стиль и обычную декорацию KWin. Ранее выполненная изолированная проверка Darkly
остаётся в отчёте ниже как историческая.


## Границы проверок и продолжение

Unit-проверки и нативные CSS-парсеры подтверждают формат, чтение токенов и
изоляцию файлов. Ранее Darkly запускался только из временного каталога в отдельном
Wayland-окне; проверка не означала системную установку и больше не является
целевым путём. Скриншоты до/после реальных KDE/GTK окон, версии toolkit и
окружение должны сопровождать следующий этап предпросмотра.
Ни генерация, ни эти тесты не меняют тему, размер текста, обои или панели.

Пользовательский установщик `desktop/install.sh` размещает KDE-палитры,
сгенерированный CSS и тему Kvantum, добавляет управляемые импорты GTK и сохраняет
резервные копии заменяемых файлов. Он не переключает системную палитру или Qt
widget style и не перезапускает приложения. Для этих настроек используются
параметры Plasma/KDE; они остаются отдельными от светлого/тёмного режима Sirca.
Установщики lock screen и SDDM запускаются отдельно.
