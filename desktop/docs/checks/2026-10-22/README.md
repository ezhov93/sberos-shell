# DESKTOP-001: установка палитр и проверка в Wayland

Дата: 2026-10-22. Основание установки — прямой запрос пользователя
«давай установим и провери». [Карточка задачи](../../../../docs/tasks/DESKTOP-001.md).
Сценарий `09-02`; `09-01`/`09-06` затронуты сохранением настроек,
но целиком не проверены.

## Окружение и объём

KDE Plasma 6.7.4, KWin Wayland 6.7.4, Qt 6.11.2, GTK 3.24.52, GTK 4.24.1.
Пользовательская KDE/Wayland-сессия, исходный GTK theme — Breeze.
Тестовые окна показывают содержимое стандартных Qt Widgets и GTK 3 контролов;
снимки не включают серверные декорации окон и содержимое рабочего стола.
Qt-окно сохраняло собственный `QWidget::grab()`, GTK 3 — собственное содержимое
через `gtk_widget_draw()`/Cairo. Это реальные Wayland-окна, не offscreen.
Окна автоматически закрывались через 1–2 секунды; все exec-сессии завершились.

Установлены обе схемы `~/.local/share/color-schemes/SberOS{Light,Dark}.colors`.
Для GTK 3/4 установлен `~/.config/gtk-{3,4}.0/sberos.css`, импорт в `gtk.css`
добавлен после существующего содержимого. Текущий режим — **SberOSDark**.
Системные плагины, Darkly, декорации, иконки, шрифты, обои и shell не устанавливались.

## Что прошло

- 5 тестов `python3 desktop/tests/test_sber_theme.py -v`.
- Генерация обеих тем и разбор CSS нативными парсерами GTK 3/4 с таймаутом 15s.
- `plasma-apply-colorscheme SberOSLight` и `SberOSDark` успешно применили палитры в текущей сессии, в отличие от ограниченных sandbox/offscreen-проб первого этапа.
- Новое Qt-окно в каждой теме получило ровно экспортированные Window, Base, WindowText, Highlight и HighlightedText; значения сохранены в JSON рядом со снимками.
- Qt/GTK 3: просмотрены фон, текст, поле ввода, кнопка normal/disabled, checkbox, progress; Qt также показывает список с выделением. Текст и геометрия не обрезаны. Цвета и акцент обновились в обеих темах.
- Сохранён контраст KDE 4: переключатель схем сам выставлял 7, после применения восстановлено исходное значение. Остальные исходные настройки шрифтов, иконок и Qt style сверены с backup.
- Откат выполнен до повторной установки: все файлы из манифеста совпали с backup побайтно, отсутствовавшие файлы удалены. Qt runtime-палитра после отката полностью совпала с исходной.
- В конце повторно установлена тёмная палитра. CSS GTK 3/4 и импорты сверены с генерацией.

| Qt runtime | До / после отката | SberOSDark | SberOSLight |
| --- | --- | --- | --- |
| Window | `#202326` | `#232329` | `#f7f7f8` |
| Base | `#141618` | `#0f0f10` | `#f0f0f4` |
| WindowText | `#fcfcfc` | `#ededed` | `#202020` |

Фактическое выделение неактивного списка может отличаться от Highlight:
исходный стиль KDE и ColorEffects сохраняют собственную обработку состояний.
Это проверка базовой палитры; полной идентичности контролам UI Kit пока нет.

## Откат текущей установки

Копия текущей установки хранится локально:

```sh
python3 ~/.local/state/sberos-desktop/backup-20261022-195010/restore.py
```

Backup содержит манифест исходных файлов, их копии и временную схему для
перезагрузки исходной палитры KDE. Скрипт возвращает весь сохранённый
`kdeglobals` и перечисленные GTK-файлы. Это снимок до установки: более поздние
изменения этих файлов при таком откате будут заменены сохранёнными.
Сами копии пользовательской конфигурации в Git не включены.

## Ограничения

GTK 4/libadwaita: CSS установлен и разобран парсером, отдельного визуального
теста нет. Accessibility не проверена: GTK 3 сообщил об отсутствии
`/run/user/1000/at-spi/bus_1`. Наведение, нажатие, все статусы и фокус,
декорации, lock и сторонние приложения целиком не проверены. Старые открытые
приложения могут требовать перезапуска.

Бывший `glass-mode` удалён. Выбор темы в оболочке, смена темы в System Settings
и ручной CSS SberOS остаются раздельными. Автоматическое согласованное переключение
KDE/GTK и сохранение оформления после повторного входа не проверены.
Полного установщика SberOS в репозитории пока нет: это ручная установка палитр
с проверенным откатом, а не завершение DESKTOP-001.


## Darkly Qt Widgets style

По запросу на изменение Darkly его Qt 6 style собран в `/tmp/sber-darkly-build`
с `BUILD_QT5=OFF`, `BUILD_QT6=ON`, `WITH_DECORATIONS=OFF` (целевой `darkly6`).
Сборка прошла; у vendored upstream кода есть предупреждения компилятора в
`darklystyle.cpp`. Системный Qt-плагин в этой среде не найден, поэтому собранный
`darkly6.so` подключался тестовым окном через временный путь поиска Qt-плагинов.
KDE-схема и Darkly config (`CornerRadius=8`, opacity=100%, Dolphin transparent=false)
загружались из отдельного временного профиля. Ни `/usr`, ни системный KDE style
не менялись: активным стилем системы остаётся Breeze.

В обоих режимах Qt подтвердил `style=Darkly::Style`, `platform=wayland`; Window,
Base и Highlight совпали с соответствующими SberOS схемами. Снимки показывают
реальную отрисовку контролов именно собранным Darkly с SberOSLight/SberOSDark.

| Режим | Снимок |
| --- | --- |
| SberOSDark + Darkly | [dark](darkly-dark.png) |
| SberOSLight + Darkly | [light](darkly-light.png) |

Сама цветовая схема уже поставляется через KDE. Ресурсы `darkly.kcfg` и
генерируемый manifest теперь задают общие радиусы и непрозрачность для плагина.
Для применения ко всем Qt-приложениям нужен отдельный пакет/установка Qt-плагина;
текущую тему Breeze пользовательских приложений эта сборка не переключала.
