# Спецификация SberOS DE

## Назначение и статус

Цель инициативы — управляемая графическая среда SberOS со стабильными привычными сценариями и безопасным программным управлением, включая AI. Исходный бриф имеет статус «Концепция инициативы». Документы описывают целевую среду; наличие требования не означает наличие реализации.

Проблемы, заявленные в брифе: зависимость развития UX от GNOME, хрупкость расширений, сложность диагностики, стоимость интеграции и сопровождения двух графических сессий. Презентация описывает исходную среду как GNOME 48 с патчами Shell, приложений и расширениями. Это сведения источника, а не проверенный состав данного репозитория.

## Навигация для агента

1. Прочитать [ограничения продукта](rules/product.md).
2. Проверить [ADR и их статусы](adr/README.md): предложение не считать утверждённым выбором технологии.
3. Найти затрагиваемые ID в [реестре 270 сценариев](rules/README.md); проверить связанные области.
4. Проверить [открытые вопросы](rules/open-questions.md) и [критерии приёмки](rules/acceptance.md).
5. В изменении указать ID сценариев, выполненные проверки и ограничения результата. При изменении смысла требования обновить его источник в Markdown и объяснить расхождение с исходником.

`rules/` содержит ограничения и наблюдаемое поведение. `adr/` объясняет архитектурные направления, альтернативы и последствия. Этот README задаёт контекст и маршрут чтения. Порядок чтения и формат ссылок на ID — соглашения этой Markdown-документации.

## Задачи и состояние работ

[Реестр задач](tasks/README.md) хранит план, критерии готовности, открытые вопросы,
проверки и коммиты между чатами. Задачи панели ссылаются на
[слепок Smart Panel](sources/panel/SMART_PANEL.md); статус источника и GNOME-зависимые
ограничения не означают принятого решения для Qt/KWin.

## Стартовая кодовая база

Для дальнейшей адаптации выбран проект [`shell/`](../shell/). Он перенесён из `refs/` как снимок исходного кода; Git-метаданные удалены, лицензионные файлы сохранены. По README проекта это оболочка для KDE Plasma 6 на Wayland: она заменяет панели Plasma, использует KWin и сохраняет часть интеграций с Plasma. Поэтому Sirca — исходный код для постепенной адаптации, а не завершённая реализация целевой SberOS DE.

## Общий UI Kit оболочки и приложений

[`ui-kit/`](../ui-kit/README.md) принят как общая библиотека интерфейса для
собственной оболочки SberOS и приложений её экосистемы. Здесь развиваются
переиспользуемые QML-компоненты, тема, типографика, размеры, иконки и визуальные
состояния. Оболочка и приложения используют эту основу для согласованного
интерфейса; логика рабочего стола и предметная логика приложений остаются
в соответствующих проектах.

Назначение UI Kit зафиксировано. По [ADR-0006](adr/0006-settings-ui-kit.md)
принято перевести собственное окно настроек оболочки на UI Kit;
[правила миграции и проверки](rules/settings-ui-kit.md) сохраняют существующие
параметры и точки входа. Окно переведено на компоненты UI Kit; выполнены
изолированные проверки на Qt 6.11.2/offscreen, проверка в Wayland предстоит.

Собственные настройки находятся в `shell/shell/qml/Settings.qml`. Внешнее
приложение KDE `systemsettings` и его модули пока отвечают за системные
параметры; их замена не входит в это решение.

Адаптация GNOME-спецификации Smart Panel к текущему прототипу описана в
[таблице переноса](rules/panel-adaptation.md). Она отделяет действующие рамки,
черновые требования и согласованные решения PANEL-000: собственный стек,
без адаптации под GNOME; корпоративные настройки вне MVP, меню открывает настройки shell.

## Визуальная цель MVP

По прямому решению пользователя от 2026-10-25 интерфейс MVP должен соответствовать
[интерактивному HTML-моку](mock/smart-panel/index.html). Эталон — основной режим
с прозрачностью и blur; размеры и графика уточняются по SVG. Цель общая для Sirca
и NextKDE/Quickshell, с отдельной приёмкой каждой реализации. Поведение реальных
сервисов определяется ТЗ и решениями MVP. Подробности: [ADR-0011](adr/0011-mock-visual-target.md),
[правила сверки](rules/mock-parity.md), [задача соответствия](tasks/PANEL-MOCK-PARITY.md).

## Расположение панели

По [ADR-0008](adr/0008-unified-bottom-panel.md) оболочка использует одну нижнюю
панель вместо отдельного дока и верхней панели. Системные popup открываются вверх.
Старый ключ `panelLayout: "split"` игнорируется. [Правила и проверки](rules/unified-panel.md)
описывают текущую раскладку и границы паритета.

По [ADR-0010](adr/0010-dual-base-hypotheses.md) проект проверяет Sirca Shell
и NextKDE/Quickshell как две возможные основы на сопоставимых сценариях.
Разработку вести отдельными задачами в соответствующих проектах; итоговый выбор
отложен до сравнения результатов и Go/No-Go.
