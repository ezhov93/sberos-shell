# ADR-0011: Принять HTML-мок как визуальную цель MVP

- **Статус:** Принято 2026-10-25; перенос в оболочки в работе.
- **Основание:** прямое указание пользователя «всё теперь ровнять по этому моку», «цель MVP — соответствовать моку» и выбор «Основной режим мока: прозрачность и blur».
- **Область:** интерфейс MVP, представленный в `docs/mock/smart-panel/`; Sirca и рабочая копия NextKDE/Quickshell.
- **Связи:** ADR-0006/0007 — UI Kit; ADR-0008 — нижняя панель; ADR-0009 — состав MVP; ADR-0010 — две основы.

## Решение

Основной визуальный ориентир — [живой HTML-мок](../mock/smart-panel/index.html).
Исходная версия этого решения — коммит `6e48fb5`; его геометрия, композиция,
иконки, поверхности, тексты элементов и показанные визуальные состояния задают
цель реализации. SVG уточняют размеры и происхождение графики; PNG дополняют
отсутствующие состояния. Согласованные изменения эталона фиксируются в Git.

Эталонный вид включает прозрачность и фоновое размытие основного режима мока.
Это заменяет прежний запрет прозрачности/blur для показанных поверхностей
в ADR-0008/0009 и задачах SHELL-001/QS-001/PANEL-010/012. Непрозрачный режим
HTML остаётся вспомогательным средством сравнения. Старые результаты сохраняют
историю этапов, но не подтверждают соответствие новой визуальной цели.

Соответствие реализуется отдельно в `shell/` и `quickshell/`. Общие компоненты,
материалы, графика и токены развиваются через UI Kit. Способ фонового размытия
проверяется на каждой основе с учётом её рендеринга и Wayland-интеграций;
конкретный compositor plugin этим решением не выбран. Сторонние исходники в
`refs/` сохраняются неизменными.

## Границы

Демонстрационные данные, сообщения о запуске и подтверждения HTML не заменяют
реальные приложения, уведомления, поиск документов и управление устройствами.
ТЗ и явные решения пользователя продолжают определять системное поведение,
безопасность, доступность и состав MVP. В частности, корпоративные настройки
и поиск остаются исключёнными; два действия питания с обновлением, исключённые
пользователем в PANEL-012, не возвращаются из демонстрационного меню HTML.

Мок содержит известные пробелы и ещё не прошёл полную браузерную сверку
(PANEL-011). Каждое обнаруженное противоречие фиксируется в задаче с конкретным
состоянием; не считать его разрешённым общей формулировкой «соответствует моку».
Для экранов, отсутствующих в моке, нужны отдельные критерии и визуальный образец.

## Приёмка и последствия

Целевая базовая сцена — 1920×1080. Сравниваются одинаковые состояния, тема,
масштаб/DPR и фон; результат подтверждается снимками и перечнем расхождений
отдельно для каждой оболочки. Адаптация других размеров и реальная системная
работа проверяются самостоятельно. Точные правила — [mock-parity.md](../rules/mock-parity.md).

Общая работа отслеживается в [PANEL-MOCK-PARITY](../tasks/PANEL-MOCK-PARITY.md),
реализации — в существующих карточках блоков. Принятие цели не означает готовность
интерфейса или выбор одной основы DE.
