# Требования и сценарии

## Как применять

- P0 — критичный, P1 — значимый, P2 — дополнительный: значения исходной карты, не готовые этапы релиза.
- ID вида `01-24` стабилен; ссылайтесь на него в задачах, тестах и отчётах.
- «Когда» задаёт контекст проверки; «Минимум» — наблюдаемый результат и ограничения UX.
- Формулировки «сохранить» описывают требуемый паритет по источнику, но не доказывают текущее поведение кода.
- Будущие возможности и неясности остаются явно помеченными. Их нельзя автоматически объявлять реализованными или исключать из рассмотрения.
- Дополнения этой документации (порядок чтения, формат отчёта, группировка ADR) отделены от перенесённых требований ссылками на источник.
