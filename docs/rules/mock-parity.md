# Соответствие MVP интерактивному моку

Основание: решение пользователя от 2026-10-25 и [ADR-0011](../adr/0011-mock-visual-target.md).
Цель MVP — соответствовать [HTML-моку Smart Panel](../mock/smart-panel/index.html)
в основном режиме с прозрачностью и blur. Правило применяется к Sirca (`shell/`)
и рабочей копии NextKDE/Quickshell (`quickshell/`).

## Приоритет источников

1. Явные решения пользователя определяют состав MVP и исключения.
2. Для визуальной реализации использовать HTML-мок: расположение, размеры,
   отступы, радиусы, графику, поверхности и показанные состояния. Исходная
   версия эталона — `6e48fb5`; при сверке записывать фактический коммит мока.
3. SVG в `docs/sources/panel/svg/` уточняют геометрию и происхождение графики.
   PNG дают дополнительные состояния, особенно тёмную тему.
4. FT/UI и правила сценариев определяют работу реальных системных сервисов,
   фокус, доступность, мониторы, ошибки и состояния, которых в демо нет.

Существующий внешний вид Sirca/NextKDE не является основанием изменять эталон.
Изменения мока как цели согласовывать с пользователем и фиксировать вместе
с причиной и влиянием на обе реализации. Обнаруженные ошибки мока вести в PANEL-011.

и Quickshell отдельно. Настройки и другие экраны вне мока требуют своего образца.

## Перенос в QML

- Базовая сцена — 1920×1080 при масштабе 100%; сравнивать логические размеры
  при известном DPR. На других экранах адаптировать раскладку с сохранением
  доступности действий; масштабирование всей HTML-сцены не является алгоритмом QML.
- Геометрию и состояния переносить в QML оболочки. Переиспользовать только
  имеющиеся подходящие API и токены UI Kit; отсутствующие элементы реализовывать
  отдельными QML-компонентами внутри `shell/` либо `quickshell/`. Для этой задачи
  общий UI Kit не расширять. Данные и сервисная логика принадлежат оболочке.
- Фоновое размытие действует на содержимое за поверхностью; текст, иконки и
  контролы сохраняют резкость. Маски ввода, скругления, резервирование края,
  управление окнами и фокус проверяются отдельно.
- Демонстрационные дата, сети, приложения, документы и три уведомления —
  образцы содержимого. В QML показывать реальные данные, сохранять рабочие
  интеграции и состояния загрузки/ошибок. Совпадение списка demo-приложений
  не является требованием к установленным приложениям пользователя.

## Известные расхождения эталона и границ MVP

- HTML-меню питания версии `6e48fb5` содержит два демонстрационных действия
  с обновлением. Они исключены пользователем в PANEL-012; реализовать пять
  согласованных действий. В текущем этапе демо исправлено по этому решению;
  исходный SVG сохранён без изменений.
- В SVG три точки Launchpad, но предоставлено 32 приложения; HTML имеет одну
  страницу. Реальная пагинация определяется количеством установленных приложений.
- В SVG уведомлений счётчик 5 и три видимые карточки; в HTML счётчик 3.
  Реальная реализация считает свою очередь, показывает/прокручивает реальные карточки.
- Текст SVG переведён в контуры; имя исходного шрифта неизвестно. Различия
  метрик шрифта и графики фиксировать при визуальной сверке, не объявлять совпадением.
- Браузерная визуальная проверка HTML остаётся незавершённой в PANEL-011.

## Критерии визуальной приёмки

Для каждой основы и каждого затронутого состояния:

1. Записать ID сценариев/FT, коммит мока и реализации, тему, состояние,
   Qt, платформу, размеры, масштаб/DPR и обои.
2. При одинаковых условиях сопоставить мок и живой QML: геометрию, графику,
   цвета, прозрачность/blur, текст, hover/pressed/disabled/focus/selected.
3. Сохранить снимки до/после и перечислить конкретные оставшиеся расхождения.
4. Проверить открытие/закрытие, дочерние уровни, Esc, Tab/Shift+Tab и реальные
   системные сценарии. Wayland, несколько мониторов и hotplug отмечать по факту.
5. Закрывать критерий только после подтверждения результата. Сборка, запуск
   процесса и снимок источника отдельно не подтверждают сходство живого QML.

Порог допустимого отклонения в пикселях не согласован; произвольный процент
похожести не вводить. Отсутствующие доказательства сохранять открытыми в карточке.
