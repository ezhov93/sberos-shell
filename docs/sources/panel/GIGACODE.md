# GIGACODE.md — SberOS Smart Panel (проект Ussuri): технические требования

> Этот каталог — выгрузка (слепок) вики-страниц `confluence.sberbank.ru`, space `SBOS`,
> проект **Ussuri**. Содержит сводный и поблочные **технические требования (СТ)** к новому
> GNOME Shell-расширению **Smart Panel** — нижней панели задач SberOS.
> Дата слепка: **2026-10-22**.

## Что это за каталог

Это **не код-проект**, а набор документации для реализации. Документы описывают функциональные
(`FT_...`) и UI (`UI_...`) требования к элементам новой нижней панели SberOS. Они используются
как источник истины при разработке расширения и при анализе/уточнении требований аналитиком.

## Как пользоваться каталогом

1. **Начни с `SMART_PANEL.md`** — он задаёт контекст: статусы требований, системные
   ограничения (SberBook / GNOME / X11+Wayland) и карту блоков. Каждый поблочный файл ссылается
   на него.
2. **Переходи к нужному блоку** по карте в `SMART_PANEL.md`. Требования нумеруются
   `FT_SMART_PANEL_<БЛОК>_<N>` и `UI_SMART_PANEL_<БЛОК>_<N>`.
3. **Статус требования решает о реализуемости** (см. «Статусы требований» в `SMART_PANEL.md`):
   🟦 ДРАФТ — может измениться, 🟩 ЗАФИКСИРОВАНО — реализуемо, 🟥 ОТМЕНЕНО — игнорируется.
   В поблочных файлах статусы различаются: например, в `button-sber.md` всё ЗАФИКСИРОВАНО,
   в остальных — ДРАФТ/НОВОЕ.
4. **Скрины** в `screenshots/` иллюстрируют макеты; ссылки оформлены как относительные пути
   (`screenshots/<имя>.png`) и совпадают с перечнем скринов внутри документов.
5. **Макеты** — в `pixso.design.sber.ru` (проекты перечислены в `SMART_PANEL.md`).
   Задачи Jira: `SBOS-41433`, `SBOS-41432`.
6. **Сверяйся с первичным источником при реализации.** В ряде блоков (`oska.md`,
   `indicators.md`, `calendar.md`, `quick-settings.md`) есть ⚠️ секции «Оговорки блока» о
   несогласованной нотации индексов в вики-источнике, опечатках и ссылках, которых нет в
   текущих FT. Не выводи из скринов того, что не оговорено в требованиях.

## Конвенции документов

- **Формат:** каждый поблочный файл имеет единую структуру: шапка (часть СТ + ссылка на
  `SMART_PANEL.md` + статус/автор) → Назначение → Термины → Системные ограничения →
  Функциональные требования (`FT_...`) → Требования к графическому интерфейсу (`UI_...`) →
  (опционально) «⚠️ Оговорки блока».
- **Обозначения:** пункты с ✎ — перечень проверяемых сценариев. Связанные требования
  помечаются «Связано: FT_...». Каждая FT/UI имеет индекс-идентификатор.
- **Статусы требований** — актуализирует аналитик; перед реализацией сверять статус
  конкретного индекса в вики-источнике (аналитическая ответственность: Блинков А.С.,
  Харитонова А.С.).
- **Границы ответственности Smart Panel** часто явно выделены («Smart Panel не переопределяет…»,
  «вне зоны Smart Panel») — при реализации соблюдать их, не расширяя функциональность.

## Служебный инструмент: `_tools/html2md.py`

Конвертирует вики-страницу (Confluence HTTrack HTML) в markdown-черновик:
- декодирует HTML-entity, размечает заголовки, таблицы требований (FT_/UI_), списки, параграфы;
- скрины превращает в `![alt](screenshots/<basename>)`.

Использование: `python3 _tools/html2md.py <file.html>` (требует `beautifulsoup4` и `lxml`).
Выдаёт черновик для последующей ручной/агентной перефразировки; исходный HTML не изменяется.
Обработка вики-страниц — конвейер: HTTrack-выгрузка → `html2md.py` → ручная редактура в
поблочные `*.md` в этом каталоге.
