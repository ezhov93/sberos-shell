# ATP-001: Адаптировать панель AeroThemePlasma для MVP SberOS

- **Статус:** В работе
- **Обновлено:** 2026-10-25
- **Источник:** [требования панели](../rules/unified-panel.md), [Smart Panel](../sources/panel/SMART_PANEL.md), [UI kit Sber mark](../../ui-kit/resources/icons/24/Sber.svg)
- **Требования:** `UI_SBEROS_PANEL_USSURI_1.1`
- **Сценарии реестра:** `03-01`, `02-02`, `09-02`, `09-24`; границы области `04`
- **Зависимости:** PANEL-000, PANEL-001
- **Основание:** запрос пользователя сравнить три основы MVP (Sirca, NextKDE и AeroThemePlasma), начав адаптацию AeroThemePlasma с панели.

## Цель и границы

Проверить, насколько панель AeroThemePlasma подходит как третья основа MVP, адаптируя её под согласованные требования и визуальный язык SberOS. Источник остаётся в `refs/aerothemeplasma/`; изменения выполняются только в рабочей копии `plasma-theme/`. Текущий этап касается стартовой геометрии панели и кнопки Сбера; меню, пятизонная компоновка и отдельные острова остаются отдельной работой.

## Критерии готовности

- [ ] Единая панель закреплена у нижнего края, сохраняет правильную геометрию, резервирование края и взаимодействие с Plasma.
- [ ] Панель содержит пять зон из правил `unified-panel.md`, Оська центрирована по экрану и не смещается от состава приложений или индикаторов.
- [ ] Блоки непрозрачны и отделены зазорами; системные popup открываются вверх.
- [ ] Кнопка Сбера открывает существующий лаунчер и визуально согласована с макетом.
- [ ] Результат можно сопоставить с Sirca и NextKDE по сценариям и ограничениям этой карточки.

### Готовность по проектам

- Sirca [x] Поведение панели и ориентир визуального оформления зафиксированы задачами PANEL-001/002.
- NextKDE [x] Компоновка переносится отдельно по PANEL-010; эта карточка касается AeroThemePlasma.
- AeroThemePlasma [ ] Геометрия и кнопка панели согласованы с MVP и проверены в Plasma.

## Неясности и ограничения

Пока не подтверждено, можно ли получить отдельные непрозрачные острова, сохранив штатные маску ввода, struts, автоскрытие и поведение окон Plasma. Панельная тема AeroThemePlasma использует собственные SVG-срезы; их визуальная пригодность для макета требует проверки в графической сессии.

## Следующий шаг

Собрать предпросмотр в Plasma и проверить панель при 1920 px в светлой и тёмной темах: отступы, высоту, кнопку запуска, резервирование нижнего края и открытие лаунчера. Затем спроектировать пять зон, сохраняя API PanelView и поведение окон.

## Проверки и результат

Первый статический срез в согласованной области: шаблон панели задаёт нижний край, пробную высоту 64 px и плавающий режим. Высоту и форму поверхности надо уточнить после снимка в Plasma. Оформление кнопки лаунчера отложено: её QML находится вне согласованных папок.

Три пакета установлены через `kpackagetool6` только для пользователя: shell — `~/.local/share/plasma/shells/io.gitgud.wackyideas.desktop`, шаблон — `~/.local/share/plasma/layout-templates/io.gitgud.wackyideas.taskbar`, панель — `~/.local/share/plasma/plasmoids/io.gitgud.wackyideas.panel`. Шаблон панели использует штатные applet IDs Plasma: `org.kde.plasma.kicker`, `org.kde.plasma.taskmanager`, `org.kde.plasma.keyboardlayout`, `org.kde.plasma.systemtray`, `org.kde.plasma.digitalclock`, `org.kde.plasma.showdesktop`; обновлённый пакет зарегистрирован через KPackage. Визуальный запуск на Plasma 6.7.4 проверен: shell-плагин не загружает `Desktop.qml`, потому что отсутствует QML-модуль `aeroshell.utils` и тип `DesktopEditMode`; из-за этого у containment `panel` остаётся `null`. Текущую раскладку восстановил из копии, SHA-256 совпадает. Отдельный тестовый `plasmashell` остановлен; работающий `./build/bin/sirca-shell` оставлен без изменений. `sirca-shell-switch status` отражает systemd-сервис, поэтому не показывает этот вручную запущенный процесс. Системный установщик AeroThemePlasma не запускался, сетевых загрузок при пакетной установке не было. Ранее CMake-конфигурация исходного проекта остановилась на недостающих KF6 dev-компонентах; установка этих трёх пакетов их не собирает.
