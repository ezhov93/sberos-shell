# ATP-001: Проверить AeroThemePlasma как дополнительную основу

- **Статус:** В работе
- **Обновлено:** 2026-10-25
- **Источник:** [требования панели](../rules/unified-panel.md), [Smart Panel](../sources/panel/SMART_PANEL.md), [визуальная цель](../adr/0011-mock-visual-target.md)
- **Требования:** `UI_SBEROS_PANEL_USSURI_1.1`
- **Сценарии реестра:** `03-01`, `02-02`, `09-02`, `09-24`; границы области `04`
- **Зависимости:** PANEL-000, PANEL-001
- **Основание:** запрос пользователя сравнивать три основы (Sirca, NextKDE и AeroThemePlasma), начав проверку AeroThemePlasma с панели; сравнительная рамка зафиксирована в ADR-0010.

## Цель и границы

Проверить реализуемость панели AeroThemePlasma в рамках сравнения трёх основ: адаптировать стартовую геометрию и кнопку Сбера к общим требованиям, зафиксировать ограничения стека и трудоёмкость, затем сопоставить результат с Sirca и NextKDE по тем же критериям. Визуальный ориентир — HTML-мок MVP по ADR-0011 для затронутых поверхностей. Источник остаётся в `refs/aerothemeplasma/`; изменения выполняются только в рабочей копии `plasma-theme/` и согласованных подпапках. Оценка AeroThemePlasma не означает выбор основы для поставки.

## Критерии готовности

- [ ] Единая панель закреплена у нижнего края, сохраняет правильную геометрию, резервирование края и взаимодействие с Plasma.
- [ ] Панель содержит пять зон из правил `unified-panel.md`, Оська центрирована по экрану и не смещается от состава приложений или индикаторов.
- [ ] Геометрия, разделение блоков и материал с прозрачностью/blur соответствуют HTML-моку; системные popup открываются вверх.
- [ ] Кнопка Сбера открывает существующий лаунчер и визуально согласована с макетом.
- [ ] Результат можно сопоставить с Sirca и NextKDE по сценариям и ограничениям этой карточки.

### Готовность по проектам

- Sirca [x] Поведение панели и ориентир визуального оформления зафиксированы задачами PANEL-001/002.
- NextKDE [x] Компоновка переносится отдельно по PANEL-010; эта карточка касается AeroThemePlasma.
- AeroThemePlasma [ ] Геометрия и кнопка панели согласованы с MVP и проверены в Plasma.

## Неясности и ограничения

Изолированный запуск shell-плагина AeroThemePlasma теперь создаёт и показывает панель в графической сессии. Временный профиль подтверждает `shell=io.gitgud.wackyideas.desktop`, containment `io.gitgud.wackyideas.panel` и штатные applet ID. Более ранний снимок `/tmp/plasma-islands-check-20261025.png` действительно был Sirca и не является доказательством работы темы; снимок `/tmp/aerothemeplasma-debug9/current.png` относится к AeroThemePlasma. На последнем снимке островки уже отрисовываются, однако под ними остаётся визуально заметная общая полоса. Зазоры маски ввода, struts, автоскрытие и поведение окон Plasma ещё не проверены. Штатные апплеты пока не дают функциональные зоны Сбера и Оськи из мокапа.

## Следующий шаг

Убрать общую подложку панели, сохранив видимые островки и корректную маску ввода; затем заменить временные группы штатных апплетов на зоны из мокапа. После этого проверить панель при ширине 1920 px в светлой и тёмной темах, включая резервирование нижнего края и открытие popup.

## Проверки и результат

Первый статический срез в согласованной области: шаблон панели задаёт нижний край, пробную высоту 64 px и плавающий режим. Высоту и форму поверхности надо уточнить после снимка в Plasma. Оформление кнопки лаунчера отложено: её QML находится вне согласованных папок.

Три пакета установлены через `kpackagetool6` только для пользователя: shell — `~/.local/share/plasma/shells/io.gitgud.wackyideas.desktop`, шаблон — `~/.local/share/plasma/layout-templates/io.gitgud.wackyideas.taskbar`, панель — `~/.local/share/plasma/plasmoids/io.gitgud.wackyideas.panel`. Шаблон панели использует штатные applet IDs Plasma: `org.kde.plasma.kicker`, `org.kde.plasma.taskmanager`, `org.kde.plasma.keyboardlayout`, `org.kde.plasma.systemtray`, `org.kde.plasma.digitalclock`, `org.kde.plasma.showdesktop`; обновлённый пакет зарегистрирован через KPackage. В `DesktopEditMode.qml` удалены `aeroshell.utils`, SDDM-фон и вызов `kreadconfig6`; режим редактирования использует локальный цветовой фон. Первый запуск до этого изменения остановился на отсутствующем `aeroshell.utils`. Раскладка Plasma восстановлена из копии, SHA-256 совпадает. Системный установщик AeroThemePlasma не запускался, сетевых загрузок при пакетной установке не было. Другие части темы вне согласованных папок всё ещё ссылаются на `aeroshell.utils` (экран входа/блокировки и splash/logout); в этой задаче они не менялись.

Изолированный GUI-запуск после удаления `aeroshell.utils` выполнен 2026-10-25 с временными `XDG_CONFIG_HOME` и `XDG_CACHE_HOME`. Ошибки импорта `aeroshell.utils` больше нет. Однако в конфигурацию попали старые applet ID из `shells/.../contents/layout.js` (`SevenStart`, `seventasks`, AeroTheme system tray/clock/show-desktop), которые не установлены; шаблон со штатными applet ID фактически не подтвердился. Также журнал содержит `Desktop.qml:127` (undefined для bool), `Panel.qml:35` (null при чтении `devicePixelRatio`) и обращения панели к отсутствующему `root.panel`. Поэтому запуск и визуальная проверка панели не пройдены; сценарии `03-01`, `02-02`, `09-02`, `09-24` остаются непроверенными. Остановлен только процесс тестового запуска; пользовательский `plasma-org.kde.plasma.desktop-appletsrc` не менялся, его SHA-256 остался `700b66eb0d6214e344592f4261f76e38c1658f19394129f65fc4a37006cace50`.

Диагностика 2026-10-25 подтвердила источник старых applet ID: при первой раскладке Plasma выполняет `contents/layout.js` активного shell-пакета. В AeroThemePlasma этот файл сам создаёт панель с AeroTheme applet ID. Отдельный `layout-templates/.../contents/layout.js` не подменяет стартовый скрипт; `contents/main.js` с `loadTemplate()` не запускается как стартовая раскладка. Это соответствует описанию [Plasma Desktop scripting](https://develop.kde.org/docs/plasma/scripting/): первая раскладка берётся из `layout.js` shell-пакета. Значит, исправить первичный запуск можно только изменив shell `contents/layout.js` либо отдельно запустив шаблон в уже созданной конфигурации. Первый вариант выходит за ранее заданную область `layout-templates`, panel plasmoid и `shells/.../contents/views`; до решения области он не менялся.

По уточнению пользователя область расширена на `plasma-theme/plasma/shells/io.gitgud.wackyideas.desktop`. Стартовый `contents/layout.js` переведён на те же штатные applet ID и нижнюю плавающую панель высотой 64 px, что и шаблон. В panel plasmoid синхронизированы ссылки task manager/show desktop на штатные ID, защищены начальные обращения к `PanelView` и вложенным applet объектам; дефолт панели изменён на 64 px и floating. В shell views исправлено bool-выражение загрузчика обоев. Ошибки `Panel.qml` с `devicePixelRatio` и null containment больше не воспроизводятся при запуске с этой раскладкой; исходный код `Panel.qml` не менялся.

Повторный запуск в свежем временном профиле выполнен на Plasma 6.7.4. В сохранённом `appletsrc` присутствуют `org.kde.plasma.kicker`, `taskmanager`, `systemtray`, `digitalclock`, `showdesktop`; в журнале больше нет ошибок с отсутствующими AeroTheme applet ID и прежних QML null-ошибок. Скриншот предпросмотра: `/tmp/plasma-theme-preview-20261025-c.png` (3840×2400). Нижняя панель отображается. На рабочем столе остаётся ошибка загрузки пустого компонента: defaults shell ссылается на `io.gitgud.wackyideas.desktopcontainment`, пакет которого отдельно не установлен; это не мешает отображению панели. Процесс тестового запуска остановлен; обычный пользовательский appletsrc не менялся. Проверены только запуск и наличие апплетов, без проверки сценариев `03-01`, `02-02`, `09-02`, `09-24`, светлой/тёмной темы и ширины 1920 px.

По запросу пользователя пакет `io.gitgud.wackyideas.desktopcontainment` установлен/обновлён для текущего пользователя в `~/.local/share/plasma/plasmoids/`. Поскольку Plasma 6.7.4 уже предоставляет системный `org.kde.private.desktopcontainment.folder`, восемь QML-файлов пакета переведены на этот модуль; отсутствующий в системной версии `Folder.RubberBand` заменён эквивалентом на QML `Rectangle`. `kpackagetool6 --show io.gitgud.wackyideas.desktopcontainment` подтверждает регистрацию, а установленный пакет совпадает с рабочей копией по `main.qml`. Первая попытка запуска в offscreen-профиле не завершилась: Plasma упала в окружении без графического дисплея; затем пакет проверен в обычной графической сессии (результат ниже). Сборка собственного C++-плагина не выполнялась: отсутствует `libplasmaactivities-dev`, а пакетный менеджер в этой сессии не имеет root-доступа. Установка KPackage использовала локальную копию проекта; при offscreen-аварии KCrash пытался разрешить `autoconfig.kde.org`, но сетевое имя недоступно.

Повторная проверка по просьбе пользователя: сначала остановлены найденные ручные процессы Sirca PID `62689` и `68631`; `sirca-shell.service` был inactive/disabled, Plasma panels были in place. Пакет обновлён и запущен в реальной графической сессии через `plasmashell --no-respawn --shell-plugin io.gitgud.wackyideas.desktop` с временными каталогами конфигурации. Для Plasma 6.7 удалены вызовы `Positioner.loadAndApplyPositionsConfig()` и обработчик отсутствующего сигнала `hasRefreshed`, удалено использование несуществующего `ViewPropertiesMenu.sortMenu`; для загрузки делегата добавлен fallback DPI, когда `Window.window` ещё не задан. В свежем журнале этих QML/API-ошибок нет; тестовый `appletsrc` содержит `io.gitgud.wackyideas.desktopcontainment` и штатные `kicker`/`taskmanager`. На снимках `/tmp/plasma-theme-live-check-20261025b.png` и `/tmp/plasma-theme-live-check-20261025-final.png` видны рабочий стол и файл `README.md`; на первом также открыто его контекстное меню. Тестовый `plasmashell` оставлен работающим, PID `72994`; панели стандартной Plasma остались на месте. Остались предупреждения геометрии экрана, подключения Kameleon для яркости, захвата мыши и KIO null-параметров; сценарии панели, темы и ширина 1920 px этим запуском не проверялись.

По запросу пользователя панель переведена на прозрачную общую основу с плавающими поверхностями штатных апплетов. Настройки внесены в стартовую раскладку shell, шаблон панели и дефолт панели. API `Panel` в QML привязан к актуальному модулю `org.kde.plasma.shell.panel`; enum в JS-раскладке оставлен в форме API класса `Panel`. Для DPI добавлен fallback до создания окна. Пакеты shell, панели и шаблона обновлены в пользовательской установке. Первоначальный снимок `/tmp/plasma-islands-check-20261025.png` ошибочно принят за тему: он показывает Sirca (ручной PID `80971`), а не AeroThemePlasma; процесс остановлен по прежней просьбе пользователя запускать тест без Sirca. Чистый снимок `/tmp/plasma-islands-final-20261025.png` показывает стандартную Plasma-панель, пользовательская панель AeroThemePlasma не отображается. В журнале при старте остаётся `requesting unexisting screen geometry -1`; DPI-ошибка и ошибки enum после последних изменений не воспроизводятся. Сценарии `03-01`, `02-02`, `09-02`, `09-24`, визуальная геометрия, темы и интерактивность остаются непроверенными.

Повторная проверка островков в свежем временном профиле Plasma: `plasmashell --shell-plugin io.gitgud.wackyideas.desktop` создал панель AeroThemePlasma с апплетами `kicker`, `icontasks`, `panelspacer`, `systemtray`, `digitalclock` и `showdesktop`. Свойство `floatingApplets` само по себе не рисовало поверхности; после переноса поверхности в обычный `Item` контейнера апплета отдельные фоновые блоки стали видны. `Plasmoid.backgroundHints = NoBackground` и `Panel.Global.Translucent` убрали тему панели из FrameSvg-слоёв по коду, но на снимке ещё видна общая затемнённая полоса по ширине экрана; источник этой полосы и маска ввода требуют отдельной проверки. Журнал `/tmp/aerothemeplasma-debug9/plasmashell.log` не содержит QML TypeError/ReferenceError; остаётся внешнее предупреждение о недоступном модуле Kameleon для яркости. Установленный `main.qml` совпадает с рабочей копией по SHA-256. Скриншот сделан в окружении 3840×2400; ширина 1920 px и светлая тема не проверены. Тестовая сессия завершена.
