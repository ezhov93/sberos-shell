# DESKTOP-001: Адаптировать оформление рабочего окружения под UI Kit

- **Статус:** В работе
- **Обновлено:** 2026-10-22
- **Источник:** запрос пользователя от 2026-10-22 на рефакторинг `shell/desktop/` под стилистику библиотеки компонентов; отдельный запрос «давай установим и провери» разрешил установку палитр в текущую сессию.
- **FT/UI:** [спецификация](../README.md), [сценарии персонализации](../rules/scenarios/09-accessibility.md); точные дополнительные ссылки FT/UI определить при инвентаризации, не считать их согласованными.
- **Контракт:** [API UI Kit](../../ui-kit/docs/API.md), [токены](../../ui-kit/docs/API-tokens.md).
- **Сценарии:** `09-02` (светлый/тёмный стиль), `09-01` (сохранение обоев), `09-06` (размер текста).
- **Зависимости:** координация с [SHELL-001](SHELL-001.md) и [UIKIT-001](UIKIT-001.md); оформление самой оболочки остаётся в SHELL-001.

## Цель и границы

Превратить исходный комплект Glass Desktop в поддерживаемое оформление SberOS,
согласованное с цветами, типографикой, размерами и состояниями UI Kit в обеих темах.
KWin сохраняет управление окнами. Для KDE/Qt Widgets и GTK использовать адаптеры
токенов: подключение QML-компонентов не заменяет оформление других toolkit.

Сначала составить карту файлов, потребителей и зависимостей `shell/desktop/`.
Выделить необходимое оформление KDE, декорации окон, GTK и экран блокировки;
обоснованно определить обязательные и необязательные части. Выбор Darkly либо
другой основы декораций пока не принят. Проверить необходимость темы Plasma,
подмены OSD, оформления отдельных приложений, сторонних ресурсов и установщиков.
Удалять устаревшее только после проверки потребителей и сохранения лицензий.

Палитру Glass не развивать как независимый источник. Для адаптеров документировать
соответствие семантическим токенам UI Kit и способ получения значений без ручного
дублирования. Непрозрачные поверхности — целевое оформление; не переносить
зависимость от Glass Key, blur и принудительной прозрачности окон.

Первый этап ограничивался изолированной генерацией. Последующим прямым запросом
пользователь разрешил установку и проверку сгенерированных палитр KDE/GTK
в текущей сессии с резервной копией и проверкой отката. Установка плагинов,
замена декораций, сервисов, экрана блокировки и всей темы Plasma в этот запрос не входят.

- [x] Инвентаризация фиксирует судьбу каталогов и скриптов: оставить, адаптировать, удалить или сохранить как необязательное; проверены вызовы из оболочки и установщиков.
- [ ] Определён и документирован состав первого этапа и выбор основы оформления KDE/декораций; спорные варианты не выданы за принятые решения.
- [ ] Цвета, шрифты, размеры и состояния выбранных частей сопоставлены документированным токенам UI Kit; ограничения toolkit и исключения перечислены.
- [x] Генерация светлой и тёмной тем воспроизводима, не требует ручного редактирования результатов и не меняет пользовательскую сессию.

- [ ] Обои, размер текста и существующие пользовательские настройки сохраняются; применение и откат проверены в тестовом профиле.

- [ ] Выполнены проверки выбранных компонентов, сборка затронутых проектов и проверка API-контракта при изменении UI Kit. Сохранены снимки до/после в обеих темах с Qt, платформой и ID сценариев; Wayland-интеграции проверены в реальной сессии.

## Неясности

- Основа декораций и необходимость собственного Qt Widgets style.
- Охват GTK и экрана блокировки в первом этапе, допустимые различия toolkit.
- Интеграция установленной палитры с переключением темы оболочки; источник и формат чтения токенов уже описаны в контракте адаптера.
- Судьба настроек цвета папок и старых команд Glass.

## Проверки и результат

Первый этап: добавлен изолированный генератор KDE/GTK из ресурсов UI Kit,
без изменений кода оболочки и библиотеки, установщиков и пользовательской сессии.
[Карта миграции и контракт адаптера](../../shell/desktop/docs/SBEROS.md)
фиксируют потребителей, судьбу исходных частей, токены и ограничения.
Собственный форк декораций не выбран; шрифты, размеры, lock и применение тем
ещё не адаптированы. Первый этап не завершает общие критерии задачи.

Проверки первого этапа:

- `python3 shell/desktop/tests/test_sber_theme.py -v`: 5 тестов прошли (RGBA, непрозрачность KDE, воспроизводимость, изменение ресурсов, отказ до записи, изоляция профиля).
- Генерация `/tmp/sber-desktop-check`: 7 файлов, обе темы.
- Нативные парсеры GTK 3 и GTK 4: обе темы без ошибок и предупреждений, каждый парсер в отдельном процессе с таймаутом 15s.
- `kreadconfig6` вернул ожидаемые RGB Window и Header/Inactive, но выдал ошибки подключения к дисплею. Повтор в offscreen не завершился за 15s для каждой схемы; нативная проверка KDE не считается пройденной. Qt 6.11.2; это не проверка Wayland. Не повторять без нового основания.
- Локальные ссылки и `git diff --check`: проверены.
- Сборки shell/UI Kit не запускались: их код не изменён, сборки могут использоваться параллельными задачами. Установка, GUI, скриншоты, типографика, откат и Wayland не проверены.

## Установка и Wayland-проверка, 2026-10-22

По прямому запросу пользователя установлены `SberOSLight.colors` и
`SberOSDark.colors` в пользовательский `~/.local/share/color-schemes/`.
CSS установлен в `~/.config/gtk-{3,4}.0/sberos.css` и импортирован после
существующего содержимого `gtk.css`. Итоговая тема KDE/GTK — **SberOSDark**.
Исходные файлы, включая отсутствие файлов, сохранены; откат проверен перед
повторной установкой. Контраст KDE восстановлен в исходное значение 4 после
того, как `plasma-apply-colorscheme` выставил своё значение 7.

[Отчёт со снимками и ограничениями](../../shell/desktop/docs/checks/2026-10-22/README.md).

- KDE Plasma 6.7.4 / KWin Wayland, Qt 6.11.2; GTK 3.24.52 и GTK 4.24.1.
- Реальные отдельные Qt Widgets и GTK 3 окна открывались в Wayland в обеих темах и автоматически закрылись; снимки просмотрены. Сценарий `09-02` проверен на этих окнах.
- Runtime-палитры Qt (Window, Base, WindowText, Highlight, HighlightedText) совпали с установленными схемами для обеих тем.
- Откат восстановил все сохранённые файлы побайтно, включая исходное отсутствие файлов; runtime-палитра Qt после отката совпала с исходной.
- Проверено сохранение исходных настроек шрифтов, иконок, Qt style и контраста. Обои и настройки shell не изменялись; полные сценарии `09-01`/`09-06` не проверены.
- 5 unit-тестов повторно прошли; обе темы принимаются парсерами GTK 3/4. GTK 3 предупредил об отсутствующей accessibility bus — доступность не проверена.
- GTK 4: установку и импорт CSS проверили по файлам, синтаксис — нативным парсером; визуальная проверка GTK 4/libadwaita не выполнена.
- Проверки старых открытых приложений, всех состояний контролов, декораций, lock, автоматической смены темы и перезахода в сессию ещё не выполнены. Снимки исходного оформления есть для тёмного режима; исходный светлый режим не снимался.
- Копия для отката текущей установки: `~/.local/state/sberos-desktop/backup-20261022-195010/restore.py` (запуск через `python3`). Скрипт восстанавливает весь сохранённый `kdeglobals` и перечисленные GTK-файлы, поэтому при будущем откате учитывать изменения этих файлов после установки.
