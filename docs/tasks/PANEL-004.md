# PANEL-004: Реализовать Оську и поиск

- **Статус:** В работе
- **Обновлено:** 2026-10-23
- **Источник:** [требования](../sources/panel/oska.md)
- **Требования:** `FT_SMART_PANEL_OSKA_1–5, 7; UI_SMART_PANEL_OSKA_1–4`
- **Сценарии реестра:** 02-01–02-03, 02-11; 09-24 (области требуют детализации перед реализацией).
- **Зависимости:** PANEL-000, PANEL-001
- **Основание:** разбор источников от 2026-10-22; задача фиксирует работу, а не утверждает черновые требования.

## Цель и границы

Реализовать Оську и поиск в собственной оболочке на Qt/QML с общим UI Kit. Системную интеграцию
адаптировать по решениям PANEL-000; не переносить GNOME API и механизм расширений автоматически.
Применимы [ADR-0008](../adr/0008-unified-bottom-panel.md),
[правила панели](../rules/unified-panel.md) и [контракт UI Kit](../../ui-kit/docs/API.md).

## Критерии готовности

- [ ] Центральное поле объединяет аватар, подсказку и раскладку; реализованы явно определённые состояния и приоритет активного ввода.
- [ ] Выдача локальных приложений и документов обновляется по вводу и прокручивается отдельно от поля.
- [ ] Копирование/вставка работают; поиск и выдача не перехватывают системное сочетание Super+L.
- [ ] Проверены поддерживаемые раскладки, обе темы, фокус и сохранение запроса при системных сообщениях.

### Готовность по проектам

- Sirca [ ] Оська и поиск реализованы и проверены в Sirca по требованиям и сценариям основной карточки.
- NextKDE [ ] Оська и поиск адаптированы и проверены в NextKDE; интеграционные отличия его системных сервисов зафиксированы.

## Неясности и ограничения

По решению пользователя от 2026-10-23 корпоративный поиск исключён из MVP: FT_OSKA_6 и UI_SMART_PANEL_OSKA_5 не реализуются, кнопки перехода нет. Источник локального поиска в Sirca — существующий KRunner/Milou. AI-функции также вне MVP. Исходный файл требований сохраняется без правок.

## Следующий шаг

Проверить постоянно видимое центральное поле, раскрытие выдачи на той же
поверхности, локальные результаты приложений/документов, ввод, прокрутку, фокус,
обе темы и состояние при уведомлении. Для NextKDE определить источник локального
поиска документов; корпоративный переход не входит в MVP.

## Проверки и результат

По уточнению пользователя поиск встроен в центральную зону панели: поле постоянно
видно, а локальная выдача раскрывается над ним внутри той же поверхности. `Meta+Space`
фокусирует это поле. Сборка `cmake --build /tmp/sberos-shell-build --target
sirca-shell -j2` прошла, приложение загрузило QML. Ширина внешнего контура
выдачи привязана к ширине центральной зоны Оськи; отступы иконок и текста
выровнены с аватаром и поисковым полем. Выпадающая поверхность отделена от
центральной зоны панели зазором 16 px. D-Bus-предпросмотр передал
запрос `firefox`; KRunner сообщил, что runner Baloo не поддерживает запросы
(NotSupported). В журнале самопроверки также указано, что глобальная регистрация
горячих клавиш недоступна в этом окружении. Визуальная сверка раскрытой выдачи и
двух тем ещё не выполнена.
Корпоративный поиск исключён из MVP.

По просьбе пользователя 2026-10-23 при создании панели в подсказке Оськи первые
10 секунд показывается «Привет, Михаил! Желаю хорошего дня», затем возвращается
«Найти приложение или документ». Изменение внесено в `UnifiedPanel.qml`; отдельная
сборка и визуальная проверка этого поведения не запускались.

Уточнение пользователя 2026-10-23: ширина центрального острова Sirca ранее была
расширена по доступной ширине панели (`dockW`) без фиксированного предела 448 px.
Это изменение отменено по следующему запросу пользователя; актуальная ширина
ограничена прежним бюджетом `min(448, screenW * 0.25)`.

2026-10-23: по последней просьбе пользователя восстановлена прежняя ширина
центрального острова: `min(448, screenW * 0.25)`. Сборка `cmake --build
/tmp/sberos-shell-build --target sirca-shell -j2` прошла, оболочка запущена и
загрузила QML. Визуальная проверка на нескольких ширинах остаётся следующим шагом.
Для UI фиксировать скриншоты до/после в обеих темах, Qt/окружение и ID сценариев;
интеграции проверять в Wayland отдельно от изолированных тестов.

2026-10-23, NextKDE: центральная Оська получила редактируемое поле и передаёт запрос в
QuickSearch; код связывает запрос с app-mode выдачей по имени приложения/`desktopId` и
передаёт его в окно поиска. QuickSearch сохраняет отдельные режимы окон и буфера обмена.
Локальной выдачи документов нет; в `PlatformClient` не обнаружена операция поиска
файлов/документов. Кнопка корпоративного поиска исключена из MVP по решению пользователя.
Source preview загрузил QML (`Configuration Loaded`), но интерактивный ввод и визуальное
соответствие не проверены из-за недоступного управления указателем и неподходящего снимка
экрана. Реализацию NextKDE не считаю завершённой: поиск документов требует выбранного и
проверенного источника данных. Сценарии: 02-01–02-03, 02-11, 09-24.

После сообщения пользователя «поиск не работает» центральный остров NextKDE изменён
на кнопку открытия QuickSearch в режиме установленных приложений. Ранее остров имел
собственный `TextInput` и при вводе сразу переносил фокус в окно QuickSearch; два поля
конкурировали за фокус. Кнопка доступна мышью, Tab и Enter/Space; само окно QuickSearch
фокусирует единственное поле запроса. Сборка `./tools/kosctl build` завершилась с кодом
0, preview `./tools/kosctl run` загрузил конфигурацию (`Configuration Loaded`), QML-ошибок
нет. CUA не обнаружил окна для визуальной/интерактивной проверки; поиск документов
по-прежнему не реализован. Exec-сессия preview: `88096`.

(поиск: `git log -- docs/tasks/PANEL-004.md`).

Продолжение 2026-10-25 по визуальной цели: окно поиска приложений в Quickshell
получило размеры 456×653, положение внизу по центру, сетку результатов в четыре

Продолжение 2026-10-25 по моку: после верстки QuickSearch и обновления сетки
Quick Settings выполнен `./tools/kosctl build`, код 0. Окно поиска 456×653
размещается внизу по центру; список приложений — четыре колонки, поле с аватаром
Оськи находится снизу. HTML-эталон не открыт во встроенном браузере (схема

25.10.2026: личное фото KUser в поле поиска Оськи заменено на общий ресурс
`shell/shell/qml/oska-avatar.png`, извлечённый из аватара HTML-мока; используется
компонент `OskaAvatar.qml` с круглой маской. Сценарии: `02-01`–`02-03`. QtSvg не

26.10.2026: круглая маска через `MultiEffect` не показывала фото в работающей панели,
хотя ресурс загружался без ошибок. Аватар подготовлен как PNG с прозрачными углами и
подключён напрямую. Сценарии: `02-01`–`02-03`. Сборка прошла; на снимке Wayland виден
аватар Оськи в строке центральной панели. Светлая тема и полноэкранный Launchpad отдельно
не проверялись.
