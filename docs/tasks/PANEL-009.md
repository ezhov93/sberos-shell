# PANEL-009: Реализовать полноэкранный Launchpad

- **Статус:** В работе
- **Обновлено:** 2026-10-26
- **Источник:** [требования](../sources/panel/applications.md)
- **Требования:** `FT_SMART_PANEL_LAUNCHPAD_1–6`
- **Сценарии реестра:** 02-02; 02-04; область 04; 09-24 (области требуют детализации перед реализацией).
- **Зависимости:** PANEL-000, PANEL-003, PANEL-004
- **Основание:** разбор источников от 2026-10-22; задача фиксирует работу, а не утверждает черновые требования.

## Цель и границы

Реализовать полноэкранный Launchpad в собственной оболочке на Qt/QML с общим UI Kit. Системную интеграцию
адаптировать по решениям PANEL-000; не переносить GNOME API и механизм расширений автоматически.
Применимы [ADR-0008](../adr/0008-unified-bottom-panel.md),
[правила панели](../rules/unified-panel.md) и [контракт UI Kit](../../ui-kit/docs/API.md).
Текущий этап ограничен Sirca. NextKDE не входит в запрос и остаётся вне области.
Уточнение пользователя от 2026-10-22: Launchpad показывает текущие обои KDE как собственный размытый фон; путь получает через `Shell.plasmaWallpaper()`, поверх изображения остаётся полупрозрачная подложка UI Kit. Это локальное исключение к общему направлению SHELL-001.

## Критерии готовности

- [x] В Sirca добавлен отдельный полноэкранный экран; вызов с кнопки панели выбирает её монитор, поле поиска получает фокус.
- [x] Сетка рассчитана по референсу `launchpad-open.png`: до 8 колонок и 4 рядов, интервал 16 px, иконки около 120 px; рамка выделения ограничена карточкой приложения, а не всей высотой ряда.
- [x] Поиск локального AppsModel ограничен названиями, фильтрует сразу, выдаёт пустое состояние и очищается при открытии.
- [x] Ввод в поле Launchpad обновляет его сетку на месте; поиск не открывает отдельный диалог Оськи/KRunner. При изменении запроса выдача начинается с первой страницы.
- [x] Esc и свободный фон закрывают экран; выбор приложения закрывает его после передачи запроса на запуск.
- [x] Launchpad загружает текущие обои KDE как собственный фон и размывает изображение; полупрозрачная подложка сохраняет контраст текста и значков.
- [ ] Визуально подтвердить загрузку обоев KDE и качество размытия, сверить светлую/тёмную темы и сохранить снимки.
- [ ] Подтвердить одноэкземплярность, Wayland-геометрию, работу в обеих темах и сценарии клавиатуры; скриншоты до/после не приложены.
- [ ] Интегрировать уведомления Оськи без потери запроса и фокуса после готовности PANEL-005.

### Готовность по проектам

- NextKDE [x] Не входит в эту Sirca-задачу; влияние не распространяется на `quickshell/`.

## Неясности и ограничения

Требования остаются черновыми. Встроенный legacy-лаунчер Sirca оставлен для старого режима панели; полноэкранный экран использует локальный список приложений, без документов и корпоративного поиска. Уведомления зависят от PANEL-005. Проверки Wayland и обеих тем не выполнены.

## Следующий шаг

Собрать отдельный предпросмотр Launchpad и проверить на Wayland: монитор вызова/активный монитор, фокус при открытии, поиск по имени, страницы и Esc. Сохранить снимки обеих тем. Затем интегрировать уведомления при реализации PANEL-005.

## Проверки и результат

Реализация этапа Sirca: `Launchpad.qml`, вызов из Launchpad-кнопки объединённой панели, режим фильтрации AppsModel только по отображаемым названиям и размытый фон из `Shell.plasmaWallpaper()`. Сценарии затрагивают `02-02`, `02-04`, `09-24`; требования источника — `FT_SMART_PANEL_LAUNCHPAD_1–4` и часть `FT_SMART_PANEL_LAUNCHPAD_5`.

Сборка `/tmp/sberos-shell-build` прошла, в том числе после настройки сетки по референсу `launchpad-open.png` (иконки около 120 px) и ограничения рамки карточкой. Прямой запуск бинарника с `--open-launchpad` в пользовательской Wayland-сессии создал полноэкранное окно; журнал подтвердил создание Launchpad без QML-ошибок. Обои считываются при открытии из `Shell.plasmaWallpaper()`; в текущей конфигурации KDE это `/home/ezhov/Pictures/sberos.jpg`. Визуально подтвердить загрузку и blur инструментами этого сеанса не удалось. `sirca-shell --check` не стартовал в sandbox из-за недоступного Wayland/XCB display; offscreen-запуск завершился по лимиту 25 секунд. Обе темы и клавиатурные сценарии не подтверждены. Уведомления Оськи во время поиска, конкурентные вызовы и мультимониторное поведение требуют проверки; снимков нет.

25.10.2026: композиция Launchpad в Sirca выровнена по SVG/HTML-моку `launchpad-open`: убран отдельный заголовок, сетка использует карточки 168×148 px с шагом строк 196 px, точки страниц сделаны круглыми 12 px, поле Оськи приведено к 456×72 px с аватаром пользователя и моковой подписью. Затемнение фона выставлено по SVG (цвет `#32353e`, непрозрачность 58%). Сборка `/tmp/sberos-shell-build` и `run-panel-smoke.py --layout` прошли; smoke проверяет панель при 1920×1080, но не снимает полноэкранный Launchpad и не подтверждает blur/аватар в Wayland. Визуальная сверка двух тем и клавиатурного состояния остаётся открытой. Сценарии: `02-02`, `02-04`, `09-24`.

25.10.2026: исправлен порядок байтов у восьмизначных QColor значений в QML (`#AARRGGBB`). CSS-порядок приводил к сплошной жёлтой заливке выбранной карточки и поля Оськи; полупрозрачные цвета теперь записаны как `#18ffffff`, `#14ffffff`, `#60ffffff` и `#d92b323b`.
