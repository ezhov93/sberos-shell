# PANEL-012: Подогнать меню Сбера Sirca под SVG-макет

- **Статус:** В работе
- **Обновлено:** 2026-10-26
- **Источник:** [SVG-макет меню Сбера](../sources/panel/svg/sber%20меню.svg), [скриншоты меню](../sources/panel/button-sber.md), [правило меню](../rules/sber-menu.md).
- **Требования:** `FT_SMART_PANEL_SBER_BUTTON_2–8`; `UI_SMART_PANEL_SBER_BUTTON_MENU_1–9` с отклонениями MVP из PANEL-002.
- **Сценарии:** `02-02`, `04-07`, `09-24`.
- **Зависимости:** PANEL-002, SHELL-001.
- **Основание:** прямое указание пользователя от 2026-10-25 ориентироваться на новые SVG-макеты при доработке меню Sirca.

## Цель и границы

Подогнать геометрию и визуальные состояния основного меню Сбера в Sirca под SVG
и живой мок. По уточнению пользователя 2026-10-26 контейнер основного меню
должен совпадать с островом Сбера (72 px), не заходить на соседнюю зону панели;
пункты остаются 40×40 px с шагом 48 px. Дочернее power-menu шириной
272 px, с радиусом 16 px, строками 28 px и интервалом 4 px. Сохранять четыре
пункта MVP, пять текущих действий питания, материал основного режима HTML-мока
с прозрачностью/blur и уже
проверенное поведение. По уточнению пользователя не включать из макета действия
«Перезагрузить с обновлением» и «Выключить с обновлением».

### Готовность по проектам

- Sirca [ ] Основное меню соответствует геометрии SVG, остаётся привязано к кнопке и сохраняет взаимодействия PANEL-002; снимки обеих тем проверены при 1920 px.
- NextKDE [x] Не входит в область: эта карточка меняет только `shell/shell/`; меню NextKDE остаётся в PANEL-010.

## Критерии готовности

- [x] Основной контейнер шириной 72 px совпадает с островом и не заходит на соседнюю зону панели; пункты 40×40 px с шагом 48 px, значки смещены на 16 px от левого края.
- [x] Всплывающие подписи наведённых пунктов выключены, чтобы не перекрывать соседние строки; доступные имена сохранены.
- [x] Видимая область меню раскрывается вверх от кнопки через clipping с неподвижным нижним краем; ширина и горизонтальная позиция не анимируются.
- [x] Power-menu использует ширину 272 px, радиус 16 px, подписи «Завершить сеанс», «Перезагрузить», «Выключить», «Заблокировать экран», «Спящий режим», разделитель и подсказки сочетаний; строки без иконок, по 28 px с интервалом 4 px.
- [x] Положение дочернего уровня привязано к вызвавшему пункту; существующие четыре действия MVP сохранены.
- [x] Сборка Sirca проходит.
- [ ] Меню визуально проверено в светлой и тёмной темах при 1920 px.
- [ ] Проверены клавиатура, закрытие дочернего уровня и клик вне без выполнения системных действий.

## Проверки и результат

QML и координаты обновлены. `cmake --build shell/shell/build -j4` прошла;
`git diff --check` прошёл. Сверка исходного SVG подтвердила подписи и разделитель;
светлая/тёмная визуальная сверка и интерактивные проверки пока не выполнены.
По уточнению пользователя ширина основного контейнера изменена с 96 на 72 px,
всплывающие подписи убраны. `cmake --build shell/shell/build -j4` после правки
завершилась успешно; визуальная проверка этой геометрии ещё не проводилась.
После сообщения пользователя о раскрытии из центра добавлена вертикальная
анимация от нижнего левого края кнопки. `cmake --build shell/shell/build -j4`
после правки завершилась успешно. Установленный бинарник отличался от сборки;
сервис остановлен, старый файл сохранён в
`~/.local/state/sirca-shell/binary-backups/sirca-shell.before-menu-origin.20261026`,
новая сборка установлена и сервис запущен. SHA-256 установленного и собранного
бинарников совпадает (`920dd57c…`); `sirca-shell.service` active/running,
`MainPID=31553`, `NRestarts=0`. Журнал подтвердил загрузку QML и первый кадр панели.
Анимация меню после открытия кнопкой визуально ещё не проверена.
Пользователь сообщил, что первая анимация всё ещё выглядит как перелёт справа к
кнопке. Масштабирование заменено на раскрытие clipping-области вверх с постоянным
нижним краем у кнопки; горизонтальное движение убрано. Сборка прошла; эту версию
установили после остановки сервиса; предыдущий бинарник сохранён в
`~/.local/state/sirca-shell/binary-backups/sirca-shell.before-menu-origin-clip.20261026`.
SHA-256 установленного и собранного бинарников совпадает (`a77da754…`), сервис
active/running (`MainPID=42048`, `NRestarts=0`), журнал подтвердил QML и первый кадр.
Нужно проверить само раскрытие меню в живом окне.
`qmlpreview6` версии 6.11.2 найден; его подключение к обычной сборке не удалось
(`Failed to create wl_display` в sandbox, offscreen сообщил, что QML debugging
выключен). По просьбе пользователя напрямую запущен
`shell/shell/build/bin/sirca-shell` для осмотра в GUI, текущая exec-сессия `42384`.
Журнал подтвердил `QML loaded`, `app ready` и первый кадр нижней панели. Также
есть предупреждения регистрации Plasma/notification D-Bus сервисов; визуальный
осмотр обновлённого меню пользователем ещё не подтверждён. Условия Qt/Wayland,
темы и ID сценариев записать после проверки.

26.10.2026 раскрытие основного меню переведено на обрезаемую область, которая
растёт вверх от нижнего края, сохраняя привязку к кнопке. `git diff --check`
прошёл; сборка и визуальная проверка этого изменения не выполнялись. Проверка
обеих тем и интерактивных состояний остаётся следующим шагом.

26.10.2026 пользователь уточнил, что меню должно быть продолжением кнопки, а не
диалоговым окном. `SberMenu` перенесён из отдельного `Window` в QML-слой внутри
`UnifiedPanel`; нижняя кромка раскрываемой области привязана к локальной геометрии
острова, а окно панели расширяет input region на меню и дочерний уровень.
`cmake --build build -j4` и `python3 tests/run-panel-smoke.py --menu --binary
... --output /tmp/sber-menu-inline-offscreen2` прошли. Проверка Wayland smoke
остановилась на keyboard context menu; живое визуальное раскрытие ещё не
подтверждено. QtTest снимок показывает меню на локальном слое панели на чёрном
offscreen фоне; он не подтверждает поведение композитора. Обе темы, живое
раскрытие и клавиатурное управление остаются следующим шагом.

26.10.2026 по просьбе пользователя уточнены координаты и цвета дочернего меню
питания: горизонтальный зазор от острова — 8 px, вертикальное положение
центрируется на вызвавшей кнопке; фон, hover, вторичный текст и разделитель
используют токены UI Kit, совпадающие с цветами HTML-мока. `cmake --build build
-j4` прошла. Обе темы и раскрытие в живом окне ещё требуют визуальной проверки.

Пользователь сообщил, что с меню питания всё хорошо, и обратил внимание на
слишком прозрачный фон всей плашки. Основная поверхность переключена с токена
`Background.Default.Primary` на `Background.Default.Secondary`, как у внутренней
поверхности в HTML-моке. `cmake --build build -j4` прошла; новую степень
непрозрачности пользователь подтвердил в живом окне в текущей теме; вторую тему
ещё предстоит проверить.
