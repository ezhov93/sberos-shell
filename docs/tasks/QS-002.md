# QS-002: Переписать настройки Quickshell на UI Kit

- **Статус:** В работе
- **Обновлено:** 2026-10-23
- **Источник:** прямой запрос пользователя от 2026-10-22: перевести приложение настроек Quickshell-реализации на UI Kit.
- **Область:** `quickshell/apps/settings/`; собственное приложение настроек SberOS, не KDE System Settings.
- **Контракт:** [API UI Kit](../../ui-kit/docs/API.md), [каталог объявлений](../../ui-kit/docs/API-catalog.md), [каталог токенов](../../ui-kit/docs/API-tokens.md).
- **Сценарии:** `09-01`, `09-02`, `09-19`, `09-21`, `09-24`; уточнить связанные сценарии при инвентаризации страниц.
- **Зависимости:** QS-001 для целевого оформления Quickshell, PANEL-010 для согласования панели и точек входа. UIKIT-001 — координация при выявлении пробелов контракта.

## Цель и границы

Перевести существующее окно `kos-settings` и все его страницы на компоненты,
палитру, типографику, размеры и состояния общего UI Kit. Сохранить отдельный
процесс настроек и текущие узкие Shell IPC-контракты. Предметная логика страниц,
валидация значений, сохранение конфигурации и сервисные вызовы остаются в
Quickshell-проекте.

Ориентир пользователя: палитра UI Kit, плоский и непрозрачный интерфейс; сохранить
светлую и тёмную темы.

Работа охватывает страницы внешнего вида и обоев, панели, Dock, лаунчера,
сочетаний клавиш, уведомлений, управления питанием и сведений об интеграциях,
а также общие навигацию, окно и повторно используемые элементы. Визуальные
настройки, которые QS-001 признает ненужными, удаляются или мигрируют отдельно;
их нельзя переносить в UI Kit как действующие опции.

Это задача для Quickshell-копии. Решение ADR-0006 и уже переведённое окно
`shell/shell/qml/Settings.qml` остаются отдельным подтверждённым результатом.
`refs/NextKde/` не изменяется.

## Неясности и ограничения

Сначала выяснить точный перечень страниц и контрактов по коду `quickshell/apps/settings/`
и `SettingsBridge`; документация NextKDE служит справкой о текущем состоянии, а не
источником новых требований. Перед использованием UI Kit проверить доступность
нужных компонентов по контракту; пробелы API согласовывать и оформлять через UIKIT-001.
Проверки выполнять по корневому `AGENTS.md`; проектный `CONTRIBUTING.md` не
ограничивает их, если его указания расходятся с правилами рабочей области.

## Инвентаризация

Окно `kos-settings` — отдельный Qt Quick процесс. Сейчас в `main.qml` есть 12
активных страниц: Theme, Top bar, Dock, Launcher, Shortcuts, Integration status,
Wallpaper, Services and components, Stage scheduling, Windows and animations,
Notifications и Power. Служебная строка `Show` в `contentByPage[0]` не имеет
навигационного пункта или Loader и не является страницей. Glass debugging удалён;
статус установленного Glass-эффекта показывается только в Integration status.
Пункт KDE System Settings — отдельное действие запуска системного модуля.

`SettingsBridge` предоставляет методы appearance, wallpaper, dock, launcher,
shortcuts, notifications, integrations, language и scheduling; отдельные
`WindowSettings` и `PowerSettings` отвечают за параметры окон и питания.
Модель состояния, Shell IPC, сохранение конфигурации, каталоги обоев, права
приложений и действия системных служб остаются на стороне приложения.

| Страница | Основные поля и действия | Backend / интерфейс |
| --- | --- | --- |
| Theme | светлая/тёмная схема, язык, применить системную тему | `SettingsBridge` appearance, language |
| Top bar | видимость, объединение с Dock | `SettingsBridge` appearance |
| Dock | размер/позиция, hover, встроенные значки, группировка, стиль/видимость, бейджи | `SettingsBridge` dock |
| Launcher | размер значков, плотность сетки, начертание, сброс профиля | `SettingsBridge` launcher |
| Shortcuts | запись сочетания, сброс к умолчанию | `SettingsBridge` shortcuts |
| Integration status | обновление статуса сервисов и плагинов | `SettingsBridge` integration snapshot |
| Wallpaper | каталог/галерея, цвет/градиент, переход, slideshow, темы, spatial assets | `SettingsBridge` wallpaper |
| Services and components | статус/ресурсы spatial wallpaper, включение/отключение, cache | `SettingsBridge` wallpaper/spatial |
| Stage scheduling | sidebar, scheduling, freeze/reclaim, исключения приложений, пресеты | `SettingsBridge` stage/scheduling |
| Windows and animations | радиус, тень, кнопки, анимации minimize/close | `WindowSettings` |
| Notifications | DND, баннеры, история, previews, разрешения приложений | `SettingsBridge` notifications |
| Power | выбор доступного энергопрофиля, pending/error состояния | `PowerSettings` |

Удалённые QS-001 селекторы и Glass debugging не переносятся в интерфейс. Отдельный
read-only статус compositor Glass остаётся в Integration status как информация
о загруженной системной интеграции, а не как настройка оформления оболочки.
Основной вход — Shell из верхней панели/Dock (`DesktopAppLauncher.openSettings()`);
`kos-settings --page=...` используется для целевого открытия страниц в разработке
и smoke-проверках. KDE System Settings запускается отдельным действием из меню.

Сохраняемые функции: все поля и действия перечисленных страниц, их текущие
ограничения, сбросы, запросы и подтверждения, переходы из shell/Dock и настройки
приложений уведомлений. Список будет уточняться по мере покомпонентной миграции;
сравнение поведения после UI Kit миграции пока не выполнено.

## Следующий шаг

Проверить меню настроек в светлой и тёмной темах и пройти его клавиатурой;
затем продолжить перенос оставшихся примитивов и меню на UI Kit и сверить страницы.
Визуальные настройки Theme/Display/Glass согласовывать с QS-001.

## Проверки и результат

Инвентаризированы точка входа, 12 активных страниц, поля/действия верхнего уровня,
backend-группы и сохранённые поведенческие границы. Glass-debug страница отсутствует
в текущей реализации; `Show` — только неиспользуемая заглушка индекса. В
`quickshell/tools/kosctl`
добавлен путь `ui-kit/_build/qml` для разработки, если библиотека собрана;
`main.cpp` добавляет `$prefix/lib/qt6/qml` при самостоятельном запуске окна.
Страницы питания и пространственных обоев используют `Sber.RadioButton`,
`Sber.Label`, `Sber.Divider` и `Sber.Switch`; Launcher использует `Sber.ComboBox`
для форм-фактора, размера значков, плотности сетки и начертания. Общая рамка окна
теперь берёт светлую/тёмную палитру и типографику из `Sber.Theme`; поле поиска,
кнопки навигации и иконки переведены на UI Kit. Карточки остаются композициями
Qt Quick на токенах темы, так как отдельного Card-компонента нет в контракте API.
Профили,
доступность, pending-состояния, IPC и диагностика сервисов сохранены.
Прямое использование `Sber.RadioDelegate` вне `ListView` вызывало ошибку;
ограничение добавлено в API-контракт UI Kit. Проверка
`apps/settings/tests/power/tst_power.qml` прошла: 3/3 на Qt 6.11.2,
`apps/settings/tests/services/tst_services.qml` прошла: 3/3 на Qt 6.11.2,
Linux/offscreen; тестовые запуски выводят предупреждение `Translation file not found`.
`python3 ui-kit/tools/api_contract.py --check` прошла; каталог API актуален,
поведение этим скриптом не проверяется. `kos-settings` собран; главное окно и
разделы Launcher (`--page=4`) загрузились в `--smoke-test` на Qt 6.11.2/offscreen;
после перевода рамки на UI Kit приложение пересобрано и повторный smoke-запуск
страницы Launcher завершился с кодом 0. GUI открыт пользователю 2026-10-22
на Qt 6.11.2; `pages/tst_contracts.qml` прошёл: 17/17. Выводил предупреждения
о `Qt.callLater` в UI Kit ComboBox при уничтожении страницы и ошибку чтения
тестовых цветовых swatches, при этом все проверки завершились успешно.
Визуальную сверку скриншота не выполнял, CUA не обнаружил окно.
конфигурация CMake
вывела предупреждения о недоступных целях статических QML-плагинов, но сборка
завершилась успешно. В журнале smoke-запуска есть существующие предупреждения о
свойстве `enabled` в Liquid controls, отсутствующем файле переводов и завершающемся
IPC-процессе при раннем выходе; оставшихся `quickshell ipc` процессов не обнаружено.
UI Kit получает системный режим темы. Выявлено ограничение UIKIT-001: текущая
сборка UI Kit компилирует абсолютный `THEME_RESOURCES_PATH` к исходному
`ui-kit/resources`, поэтому самостоятельная установленная доставка темы ещё не
обеспечена. Визуальная сверка обеих тем и установленный запуск не выполнялись.

### Перенос контролов настроек на UI Kit — 2026-10-22

Заменены оставшиеся в `quickshell/apps/settings/` ссылки на `LiquidSlider`,
`LiquidGlassSwitch`, `LiquidSelect`, `LiquidNavBar`, `ColorRampSlider` и
`VectorIcon`; старые импорты удалены. Ползунки и переключатели используют
`Sber.Slider`/`Sber.Switch`, сегментные выборы собраны из `Sber.Button`, а
выпадающие списки страниц используют `Sber.ComboBox` через
`SettingsComboBox.qml`, который преобразует массивы данных в документированную
модель UI Kit. Кнопки обоев, действия плиток и поля настроек также переведены
на компоненты UI Kit; неиспользуемый `WallpaperValueMenu.qml` удалён. Shell IPC,
значения параметров и подтверждение переключателей сохранены. Тесты подтвердили,
что снимок состояния остаётся источником истины для переключателей.

Проверки на Qt 6.11.2, Linux/offscreen: сборка `kos-settings` прошла;
`kos-settings --smoke-test` завершился с кодом 0 при `QML2_IMPORT_PATH` на
`ui-kit/_build/qml`; `tests/segmented-layout` — 5/5, `tests/pages` — 17/17,
`tests/widgets` — 3/3, `tests/builtins` — 6/6, `tests/wallpaper` — 15/15.
В `tests/pages` остались предупреждения UI Kit ComboBox при уничтожении страниц,
в `tests/builtins` — ошибки чтения геометрии UI Kit TextField в offscreen; обе
группы завершились успешно. CMake сообщил, что часть статических Qt QML-плагинов
недоступна для линковки; smoke-запуск прошёл. Изолированное окно визуально не
проверялось, темы и установленная доставка UI Kit не проверялись.
Для просмотра пользователем запущен отдельный предпросмотр страницы Top bar
командой `kos-settings --page=2`; активная exec-сессия `92984`. Запуск вывел
предупреждения об отсутствующем переводе и D-Bus ClickTracker. Визуальную оценку
после запуска должен подтвердить пользователь.

### Левая навигация по концепту настроек — 2026-10-23

В `main.qml` список навигации приведён к компоновке из презентации на слайде 2:

выполнены.

### Исправления по результатам headless-проверки — 2026-10-23

Сборка и headless-набор Quickshell выполнены на Qt 6.11.2/Linux: 24/24 теста
прошли. Исправлены тестовые точки входа для страницы окон после изменения индекса
разделов (`--page=windows` и smoke-тест теперь выбирают индекс 10), а тест радиуса
проверяет реальные сигналы `Sber.Slider` и её ширину вместо отсутствующих API.
`ComboBox` UI Kit отложенное обновление `ChipGroup` перенесено в одноразовый Timer,
чтобы не вызывать callback после уничтожения страницы. Проверка
`kos-shell.dock-magnification-runtime` также прошла после удаления утверждений об
устаревших стеклянных плашках.

Живая конфигурация Quickshell загрузилась в предпросмотре; platform/data-сокеты
недоступны. Снимок активного выхода DP-5 (2560×1440) полностью чёрный, поэтому он
не подтверждает отрисовку окна настроек или панели; CUA не видит управляемых окон.
Визуальные критерии обеих тем и навигация клавиатурой не закрыты. Связанная
staging-установка UI Kit теперь проверена отдельно без build tree. Установленный
`kos-settings` загрузил `installed copy` и прошёл `--smoke-test` и
`--smoke-test-windows` с QML-модулями и ресурсами из staging-prefix; повторный тест
страницы окна прошёл при скрытом UI Kit build tree. Исходный checkout оставался
на диске, но журнал подтвердил, что приложение выбрало установленную QML-копию.

Следующий шаг: повторить снимки обеих тем на видимом Wayland-выходе и пройти
навигацию Tab/Shift+Tab; затем продолжить покомпонентную сверку оставшихся страниц.
