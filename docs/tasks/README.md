# Реестр задач

Это постоянная память о запланированной работе между чатами. Спецификация описывает
требуемое поведение, ADR — принятое решение, задача — объём работы и её состояние.
Постановка задачи не утверждает черновик источника и не означает завершённую реализацию.

## Цель MVP: соответствие моку

Решение пользователя от 2026-10-25: Sirca и рабочую копию NextKDE/Quickshell
выравнивать по [живому HTML-моку](../mock/smart-panel/index.html), включая
основной режим с прозрачностью и blur. [ADR-0011](../adr/0011-mock-visual-target.md)
заменяет старый запрет эффектов для представленных поверхностей, в том числе
в незавершённых критериях SHELL-001, QS-001 и PANEL-010/012. Их прежние проверки
не подтверждают соответствия новой цели. Критерии каждого проекта закрываются
отдельно по [правилам сверки](../rules/mock-parity.md). Уже имеющиеся компоненты UI Kit
переиспользовать; отсутствующие реализовывать в QML каждой оболочки, без расширения
общего кита ради этой задачи.

## Порядок работы

При чтении и проверках соблюдать [правила экономной работы с контекстом и командами]
(../rules/agent-workflow.md#экономная-работа-с-контекстом-и-командами).

1. Перед работой прочитать реестр и карточку по области запроса; обновить существующую,
   если запрос её продолжает. Для новой работы создать карточку со стабильным ID.
2. Указать цель, источник и FT/UI, ID сценариев, зависимости, критерии готовности,
   неясности, следующий шаг, проверки и коммиты. Не дублировать всю спецификацию.
   Критерии готовности разделять по каждой основе, входящей в область конкретной
   задачи: указать проверяемый результат либо обоснованное «не входит в область»
   с проверкой влияния. Завершение одной основы не закрывает остальные; явно
   перечислять основы, которые карточка не охватывает.
3. Начав работу, поставить «В работе». При препятствии поставить «Заблокировано»
   и записать конкретную причину и условие продолжения. Зависимости сами по себе
   не переводят запланированную задачу в заблокированные.
4. После проверенной доработки обновить карточку и строку реестра в том же коммите.
   Незавершённые критерии и пропущенные проверки сохранять явно; поставить «Готово»
   только после выполнения всех согласованных критериев, затем переместить карточку
   в `archive/` и обновить ссылки. Этап можно закоммитить,
   оставив задачу в работе. Для текущего коммита допустима ссылка через путь в Git,
   для последующих — записывать уже известные хеши; не менять коммит ради собственного хеша.
5. При изменении требований обновлять rules; при архитектурном решении — ADR.
   Источники сохранять, отклонения объяснять. Уточнения пользователя переносить
   из чата в карточку. Готовые задачи перемещать в архив, не удалять; ID не переиспользовать.

Статусы: **Запланировано**, **В работе**, **Заблокировано**, **Готово**.
В реестре и карточке статус должен совпадать. У каждой незавершённой карточки есть следующий шаг.
Активные карточки находятся в `docs/tasks/`, закрытые — в [`archive/`](archive/README.md).

## Панель

Источник — [слепок Smart Panel от 2026-10-22](../sources/panel/SMART_PANEL.md)
и его скриншоты. Анализ выявил отличия от текущего объединения панелей:
пять зон и отдельные визуальные блоки, центральная Оська, меню Сбер,
переполнение +N и полноэкранный Launchpad. Объединение из ADR-0008 остаётся
технической основой; [PANEL-000](archive/PANEL-000.md), компоновка
[PANEL-001](archive/PANEL-001.md) и меню [PANEL-002](archive/PANEL-002.md)
завершены (проверки только 1920 px по ADR-0008);
PANEL-010 переносит компоновку в Quickshell: пять островов добавлены как
промежуточная реализация, меню Сбера оформлено единой поверхностью с четырьмя
иконками MVP и дочерним power-menu справа. Снимки в тёмной теме Wayland
подтвердили совмещение с кнопкой и неподвижность иконок при раскрытии power-menu;
по уточнению пользователя отдельный верхний Bar и переключатель его объединения
удалены, оболочка создаёт одну нижнюю панель. Проверка всей панели, светлой темы
и интерактивного поведения ещё впереди. После перестройки Quick Settings
сборка `./tools/kosctl build` прошла (код 0); визуальная проверка обеих тем и
локальный QML-запуск остаются незавершёнными. Сетевые ошибки DNS при необязательной
проверке GitHub API не повлияли на сборку.
Геометрия меню Сбера Sirca подгоняется к SVG и живому моку в PANEL-012; по
уточнению 2026-10-26 основной контейнер должен быть шириной острова (72 px), не
заходить на соседнюю зону панели; раскрытие анимируется от кнопки. Четыре иконки MVP
и действующее поведение сохраняются.

В рабочей копии AeroThemePlasma (ATP-001) убран старый градиентный фон на всю ширину
раскладки. Поверхности tray, часов и «Показать рабочий стол» теперь нарисованы как
один общий системный остров внутри панели; сравнение в Breeze Light и
Breeze Dark на Plasma 6.7.4 / Qt 6.11.2 под Wayland это подтвердило. Проверка маски
ввода, нижнего strut и остальных зон ещё впереди; детали и снимки — в ATP-001.

PANEL-004 продолжает локальный поиск через существующий KRunner/Milou. По прямому
решению пользователя 2026-10-23 корпоративный поиск исключён из MVP: кнопка и
передача запроса не реализуются. В папке скриншотов есть строка Оськи и пример
системного сообщения, но нет кадров её локальной выдачи.
По уточнению 2026-10-23 ширина центрального острова Sirca должна адаптироваться
к доступной ширине панели; визуальная проверка на нескольких ширинах записана в PANEL-004.
При создании панели первые 10 секунд подсказка Оськи показывает персональное приветствие;
изменение и ограничение проверки зафиксированы в карточке PANEL-004.

В NextKDE календарь теперь открывается с часов в standalone Bar и встроенном Dock; Qt-локаль
задаёт порядок дней недели. Внешнее закрытие, мультимониторное переключение, фокус и номера
недель ещё не проверены. Центральная Оська принимает запрос и передаёт его QuickSearch приложений;
локальный поиск документов остаётся незавершённым (PANEL-004, PANEL-008).

PANEL-007 начат в Sirca: сетка обновлена до восьми плашек из макета, сохранённый
порядок нормализуется до полного набора, добавлены индикатор заряда и запуск
Spectacle, поверхности переведены на токены UI Kit.
Плашки уведомлений Оськи и авиарежима остаются недоступными до интеграций;
Wayland, визуальная сверка, синхронизация и перенос в NextKDE впереди.
26.10.2026 геометрия быстрых настроек Sirca подогнана под HTML-мок: 488×540,
заголовки регуляторов, 2×4 плитки, размеры и отступы; сборка прошла. Снимки
По обратной связи на живой кадр убраны лишняя подложка, наружный отступ и
отличия слайдеров/активных цветов; основной экземпляр перезапущен. Новая
визуальная сверка двух тем остаётся впереди (PANEL-007).

По запросу 2026-10-26 Sirca показывает самостоятельную пассивную OSD-карточку
для событий громкости, микрофона, яркости и текстовых системных состояний при
работе без `plasmashell`. D-Bus сервис уже существовал; прежний индикатор был
встроен в часы и не показывал текстовые события. Реализация и проверка отмечены
в [OSD-001](OSD-001.md); Wayland, аппаратные клавиши и обе темы ещё не проверены.

«Новое/адаптировано» у календаря и быстрых настроек обозначает происхождение,
а не утверждение. Источник описывает GNOME/X11/Wayland, проект — Qt/KWin/Wayland;

без GNOME-адаптации. Корпоративные настройки вне MVP, меню открывает настройки shell.

MULTI-001 включает панель на всех подключённых экранах по умолчанию;
`screens.<output>.panel: false` отключает выбранный выход. Задача также охватывает

## Развитие UI Kit

| Задача | Работа | Статус | Зависимости |
| --- | --- | --- | --- |
| [UIKIT-001](UIKIT-001.md) | Улучшить и поэтапно отрефакторить UI Kit | В работе | Координация с TEST-001, SHELL-001, PANEL-002 |

Первичный разбор завершён. Реализованы runtime-поиск ресурсов темы и доставка
QML-модулей UI Kit для Quickshell; полная сборка Quickshell прошла. Staging install
UI Kit проверен с несуществующим source resource path: импорт темы и CTest 3/3
прошли после сокрытия build tree. GUI-проверка оболочки на DP-5 остаётся
неподтверждённой из-за чёрного снимка выхода. Проверка установленного `kos-settings`
и его пользовательского deploy runtime остаётся в карточках QS-002/UIKIT-001.

Галерея UI Kit показывает справа список 22 компонентов с интерактивными образцами; статичные и служебные типы исключены. Для каждого элемента своя боковая вкладка, верхней полосы вкладок нет. Сборка и снимки обеих тем прошли; галерея запущена в GUI.

Повторный QML-аудит выявил и исправил подтверждённые дефекты в `AutoComplite`,
`ComboBox`, `ChipGroup`, `Pagination`, `Menu` и `Range`; сборка и CTest прошли,
API-контракт актуален. Неопределённая семантика `Colorizer.selected` и два
низкоуверенных поведения остаются в карточке UIKIT-001.

Классификация 1311 предупреждений линтера выделила два потенциальных риска
выполнения/контракта; `Loader.item` в `AutoComplite` защищён проверкой готовности,
а контекстные меню `TextArea`/`TextField` поддерживают обычный `Menu` через
`popup(x, y)`. Регрессионный QML-набор прошёл 12/12, полный CTest — 3/3. Детали и
проверки записаны в [UIKIT-001](UIKIT-001.md).
