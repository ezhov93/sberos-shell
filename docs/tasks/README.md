# Реестр задач

Это указатель на текущую работу, а не журнал изменений. Спецификация описывает
требуемое поведение, ADR — принятое решение, карточка — объём, статус, проверки
и следующий шаг. Историю и доказательства ищите в карточках; наличие задачи не
подтверждает готовность реализации.

## Цель MVP: соответствие моку

Решение пользователя от 2026-10-25: Sirca и рабочую копию NextKDE/Quickshell
выравнивать по [HTML-моку](../mock/smart-panel/index.html), включая прозрачность
и blur. Основание — [ADR-0011](../adr/0011-mock-visual-target.md), правила и
критерии приёмки — [mock-parity.md](../rules/mock-parity.md). Результат для
каждой основы подтверждается отдельно. Общие цвета и существующие подходящие
controls UI Kit сверяются по UIKIT-002; компоненты, специфичные для оболочки,
остаются в её QML.

## Порядок работы

Перед работой прочитайте этот реестр и относящуюся к запросу карточку. Новую
работу оформляйте карточкой со стабильным ID, источником и FT/UI, ID сценариев,
зависимостями, критериями готовности, неясностями, проверками и следующим шагом.

Начатую задачу ставьте «В работе». При препятствии укажите конкретную причину и
условие продолжения; сами по себе зависимости не означают блокировку. После
проверенной доработки обновите карточку и реестр в том же коммите. Критерии
готовности разделяйте по каждой охваченной основе; для исключённой из области
основы укажите обоснование и проверку влияния. Завершение одной основы не
закрывает остальные.

Статусы в реестре и карточке должны совпадать. У каждой незавершённой карточки
укажите следующий шаг. После выполнения всех согласованных критериев перенесите
закрытую карточку в [`archive/`](archive/README.md), обновите ссылки и не
переиспользуйте её ID. При изменении требований обновляйте rules, при изменении
архитектурного решения — ADR. Сохраняйте источники и объясняйте отклонения.
Подробности и коммиты ведите в карточке, не дублируйте их в этом указателе.

Статусы: **Запланировано**, **В работе**, **Заблокировано**, **Готово**.
