# SDDM-001: Подогнать экран входа по lockscreen и мокам

- **Статус:** В работе
- **Обновлено:** 2026-10-26
- **Источник:** запрос пользователя «подбей sddm (`desktop/sddm/`) по примеру с lockscreen и моками».
- **FT/UI:** [сценарии входа](../rules/scenarios/01-login.md), [SVG экрана входа](../sources/login/README.md), [интерактивный мок](../mock/login/), [экран блокировки DESKTOP-001](DESKTOP-001.md).
- **Сценарии:** `01-01`, `01-02`, `01-21`, `01-22`, `01-23`, `01-26`, `01-30`, `01-31`.
- **Зависимости:** [DESKTOP-001](DESKTOP-001.md), SDDM и QML-модули установленной Plasma.

## Цель и границы

Сверять экран SDDM прежде всего с `sddm-entry.svg` и состояниями интерактивного
мока: резкий фон, центральный знак SberOS, дата и время, карточки реальных
пользователей, действие нового пользователя и нижняя системная строка. Не применять
`WallpaperFader` к этому экрану: его blur перекрывает и размывает макет. Сохранить
реальную авторизацию SDDM, пользовательскую и сессионную модели и системные действия.
Не переносить демонстрационные фиктивные учётные записи из мока и не заявлять
недоступные способы аутентификации.

В качестве базового изображения используется встроенный растр из пользовательского
`sddm-entry.svg`; оригинальный SVG сохраняется. Live wallpaper-item KScreenLocker
до запуска пользовательской сессии недоступен. Сторонняя тема Hexabee/Breeze
остаётся атрибутированной; изменяется только `desktop/sddm/`, не содержимое `refs/`.

## Критерии готовности

- [ ] Реальный список пользователей и ввод пароля визуально сопоставлены с SVG-моком; переход выбора пользователя, ошибка входа и повторная попытка проверены.
- [x] Фон и центральный знак из `sddm-entry.svg` видны без blur/вуали; дата и часы занимают место из SVG.
- [x] Геометрия карточки, круглый аватар, типографика и действие нового пользователя визуально приближены к SVG.
- [ ] Выбор пользователя, форма пароля, неверный пароль и возврат к выбору проверены в test-mode.
- [ ] Компоненты проверены при 1920×1080 и на обоих выходах текущей сессии; для DP-5 нужен новый кадр без перекрывающего окна рабочего стола.
- [ ] Проверены раскладка, выбор сессии, переключение пользователя, Caps Lock, выключение/перезагрузка и системные ограничения действий.
- [x] Сохранены лицензии и происхождение встроенного изображения; текущий Wayland-кадр DP-4 приложен.

## Проверки и результат

26.10.2026 после повторной сверки с `docs/mock/login/index.html` прежний blur
и вуаль убраны: `WallpaperFader` темы сам размывал фон поверх контролов и
перекрывал элементы макета. В QML добавлены знак, извлечённый из SVG в PNG для
совместимости с image plugin SDDM, русские дата/время, круглые аватары и прозрачное
действие нового пользователя. Имена берутся из живой модели SDDM; тестовая модель
на обоих выходах содержит одну запись (`count=1`, `containsAllUsers=true`). Формы
входа сохраняют `sddm.login`, выбор сессии и доступные действия питания. Верхнее
поле формы получает отступ до координаты мока (`top: 72.41%`); временный test-mode
кадр подтвердил, что поле видно ниже знака. Переход по клику в живом test-mode ещё
нужно проверить.

`qmllint` завершился с кодом 0, остались предупреждения динамических API Plasma/SDDM.
`git diff --check` прошёл. Живой `sddm-greeter-qt6 --test-mode` без ошибок загрузил
тему на DP-4 (1080×1920) и DP-5 (2560×1440). Визуально проверен текущий кадр DP-4:
[снимок](evidence/SDDM-001/wayland-entry-DP-4-1080x1920.png). DP-5 в момент снимка
был перекрыт окном Dolphin, поэтому свежий кадр не сохранён. PAM-аутентификация,
ошибка входа, повторный выбор, раскладка, Caps Lock и команды питания не проверялись.

Макет использует две демонстрационные учётные записи, а экран отображает только
реальные записи SDDM; при одной записи оставлено свободное место второй карточки,
чтобы сохранить положение действия нового пользователя.
