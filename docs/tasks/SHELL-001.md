# SHELL-001: Привести оформление оболочки к HTML-моку через UI Kit

- **Статус:** В работе
- **Обновлено:** 2026-10-25
- **Источник:** прямое указание пользователя от 2026-10-22: перекрасить shell под цвета библиотеки и отказаться от прозрачности.
- **Контракт:** [UI Kit API](../../ui-kit/docs/API.md), [токены](../../ui-kit/docs/API-tokens.md).
- **Сценарии:** `09-01`, `09-02`, `09-19`, `09-21`, `09-24`; связанные области `03`, `05`, `07` уточнить при инвентаризации.
- **Зависимости:** нет; согласование GNOME-адаптации PANEL-000 не требуется для этой задачи.

## Новое решение пользователя, 2026-10-25

[ADR-0011](../adr/0011-mock-visual-target.md) заменяет исходное требование этой
карточки о непрозрачности показанных поверхностей. Цель MVP — соответствовать
основному режиму [HTML-мока](../mock/smart-panel/index.html), с прозрачностью и blur.
Сохраняются общий UI Kit, обе темы, системные функции и границы сервисов.
Прежние результаты ниже описывают выполненный этап, а не новую готовность.
Общая приёмка обеих основ отслеживается в [PANEL-MOCK-PARITY](PANEL-MOCK-PARITY.md).

## Исходная цель до ADR-0011

Согласовать оформление всей собственной оболочки с палитрой общего UI Kit:
панели, меню, popup, лаунчер, поиск, уведомления, календарь, быстрые настройки,
переключатель окон, OSD, настройки и режим редактирования. Учитывать только
единую нижнюю панель; удаление split отслеживается в SHELL-002. Цвета фонов, текста, иконок, границ, выделения и состояний
получать из семантических токенов библиотеки в светлой и тёмной темах.

Отказаться от просвечивания рабочего стола сквозь поверхности интерфейса и
от фонового blur/glass, необходимых для такого оформления. Общие компоненты
UI Kit переиспользовать по контракту; полная замена всех компонентов оболочки
не является условием этой задачи. Системные приложения, содержимое сторонних
апплетов и глобальные эффекты KWin не перекрашивать в рамках этой работы.

Это явное уточнение проекта к скриншотам Smart Panel: сохраняются компоновка
и сценарии, но прозрачные/размытые поверхности макетов не воспроизводятся.
Исходные скриншоты не изменять.

## Действующие критерии готовности

- [ ] Имеющиеся подходящие controls/tokens UI Kit переиспользуются; отсутствующие компоненты и материалы реализованы отдельно в QML `shell/`, без расширения UI Kit.
- [ ] Представленные в моке панели, меню, поиск, уведомления, календарь и быстрые настройки соответствуют его основному режиму: геометрия, графика, прозрачность и blur.
- [ ] Материал размывает содержимое за поверхностью, сохраняет читаемость обеих тем и не размывает собственные текст/иконки; резервирование края и маски ввода сохранены.
- [ ] Светлая/тёмная темы, hover/pressed/disabled/focus/selected и реальные системные действия сохранены; демонстрационные значения HTML не зашиты в рабочие сервисы.
- [ ] Соответствие подтверждено снимками при одинаковых условиях по mock-parity.md; ограничения Wayland, DPI и мониторов записаны явно.
- [ ] Оформление вне показанных моков согласовано в коде оболочки; существующие API UI Kit переиспользованы по необходимости, отсутствующие экраны не объявлены визуально принятыми.

### Готовность по проектам

- Sirca [ ] Поверхности `shell/` соответствуют моку; сборка, визуальная и поведенческая приёмка выполнены отдельно.
- NextKDE [ ] Поверхности рабочей копии `quickshell/` соответствуют тому же моку; собственная приёмка выполнена отдельно, `refs/` сохранён.

## Проверки и результат

В PANEL-001 подготовлены непрозрачные фоны пяти блоков unified и общего popup,
плоские варианты базовых индикаторов. В PANEL-002 меню Сбер и дочерние контейнеры также используют непрозрачные цвета UI Kit. Общая миграция оболочки и удаление старых
параметров не выполнены; задача остаётся запланированной. При выполнении:

- Проверить актуальность API-контракта, собрать оболочку, выполнить применимые изолированные проверки затронутых компонентов.
- Сохранить снимки до/после в светлой и тёмной темах на светлых и контрастных обоях; проверить панель и основные popup, текст, выделение и клавиатурный фокус.
- Проверить реальную Wayland-сессию без Glass, оба режима панели и старую конфигурацию прозрачности; записать Qt, окружение и результаты. Offscreen не подтверждает интеграции KWin.
- Проверить документационные ссылки и `git diff --check`; не добавлять тесты, повторяющие реализацию только ради покрытия.

## Неясности и ограничения

Точные токены и способ фонового размытия определить по инвентаризации каждой
основы. При нехватке материала или роли дополнять UI Kit и контракт; скрытый API
и параллельную палитру не вводить. Прежние проверки непрозрачного оформления
не подтверждают соответствия новому материалу. Визуальная проверка обеих тем,
DPI и Wayland выполняется по mock-parity.md.
