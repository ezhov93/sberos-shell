# UIKIT-001: Поэтапно улучшить и отрефакторить UI Kit

- **Статус:** В работе
- **Обновлено:** 2026-10-23
- **Источник:** запрос пользователя от 2026-10-22: улучшить и поэтапно отрефакторить UI Kit; последующее указание исправить девять подтверждённых QML-дефектов.
- **FT/UI:** API-контракт UI Kit; rules/settings-ui-kit.md; FT/UI задач PANEL/SHELL для затронутых потребителей. Точный состав расширять по этапам.

- **Зависимости:** TEST-001 для координации тестов; SHELL-001 и PANEL-002 для проверки потребителей. Инвентаризация не заблокирована.

## Цель и границы

Улучшить надёжность, сопровождаемость и подключение общей библиотеки оболочки
и приложений. Первичный [разбор и предложения](../../ui-kit/docs/refactoring-review.md)
содержит подтверждённые статические находки, ограничения и порядок работ. Текущий
этап исправляет дефекты TabBar, ThemeGradient, TextField, ChipGroup, Pagination,
RadioDelegate, Carousel, ComboBox и Switch. Публичные имена и сигнатуры API не
меняются; предложенные архитектурные изменения остаются неутверждёнными.

## Предлагаемые этапы

1. Регрессионные тесты и поведение TextField/ComboBox, загрузка темы, ошибки File/Process.
2. CMake, упаковка, версии и ресурсы без зависимости установленного пакета от исходников.
3. Общие состояния компонентов, типизация внутренних свойств и границы публичного API.
4. Совместимые новые имена API и матрица примеров галереи.

## Проверки и результат

Первичный статический разбор завершён: API-контракт проверяется по исходникам,
CTest существующей сборки ранее прошёл 2/2. Детали и ограничения в отчёте.

По ответу пользователя «го» выбран и реализован первый узкий этап: runtime-поиск
ресурсов UI Kit. `Sber.Theme`, шрифты и системные уведомления сначала ищут
`SBER_COMPONENTS_DATA_DIR`, затем существующий compile-time путь ресурсов для
разработки, затем стандартный data path `SberComponents/`. Установка UI Kit уже
размещает ресурсы в `share/SberComponents`, поэтому стандартная установка
библиотеки больше не требует, чтобы исходный каталог оставался на месте.
`cmake --build ui-kit/_build -j 4` прошёл; CMake выдал предупреждения о Qt policy
и неразрешённых QML plugin link targets галереи. `api_contract.py --write` обновил
fingerprint, повторный `--check` прошёл. CTest и временная установка без исходников
не выполнялись. Quickshell `kosctl` теперь собирает UI Kit в отдельный build tree
и развёртывает QML-модули/ресурсы в пользовательский runtime; RUNPATH плагинов
переписывается на относительные соседние каталоги. Отдельная сборка `kos-settings` и полная сборка `kosctl build` прошли
(с отключёнными KWin-плагинами и Spatial3D); CMake выдал предупреждения о Qt QML
plugin link targets, QTP0001 и Qt feature zstd. Сборка Quickshell сначала выявила
попытку Go писать кэш в недоступный `~/.cache/go-build`; `kosctl` теперь по
умолчанию использует `.build/kosctl/go-cache`, сохраняя переопределение `GOCACHE`.
`kosctl run` не смог открыть GUI из-за sandbox-запрета на `/run/user/1000` и
Wayland/X11. CTest и сценарий установки после изменений не проверены.

Обзор QML выявил девять подтверждённых дефектов поведения. В текущей доработке
исправлены TabBar, ThemeGradient, TextField, ChipGroup, Pagination, RadioDelegate,
Carousel, ComboBox и Switch; проверки сборкой и поведением ещё предстоят. Публичные
имена и сигнатуры API не менялись.

Для этой доработки `cmake --build ui-kit/_build -j 4` и
`python3 ui-kit/tools/api_contract.py --check` прошли. QML-линтер выполнен для
девяти компонентов и выдал 224 предупреждения; тесты поведения и CTest не запускались.

Витрина компонентов расширена. `cmake --build ui-kit/_build -j 4` прошёл;
запуск галереи и сохранение снимков светлой/тёмной темы прошли на Qt 6.11.2
в Linux `offscreen` с программным рендерером. Перечень галереи сопоставлен
с исходниками: 80 из 80 файлов. При загрузке Qt сообщает об отсутствующем
системном переводе, ресурсе иконки `Settings` и переопределении свойства `data`
в `Accordion`/`Carousel`; запуск завершился успешно. Ручное взаимодействие
в Wayland, CTest и API-контракт не проверялись.

### Staging-установка без исходников — 2026-10-23

Исправлена CMake-установка в нестандартный prefix: QML, заголовки, CMake package
конфиги и ресурсы теперь устанавливаются относительно prefix; удалены install-time
`chmod` по абсолютным путям. Плагины Theme, Controls и Widgets получают `$ORIGIN/../Core`
в install RUNPATH, поэтому не ищут Core в build tree или системном Qt каталоге.
Временная сборка использовала несуществующий `THEME_RESOURCES_PATH`; staging install
прошёл в `/tmp/ui-kit-mvp-stage`. После временного сокрытия build tree тест импорта
`Sber.Theme` и чтения светлых/тёмных палитр прошёл 3/3, а `ctest` отдельной сборки
прошёл 3/3 с `SBER_COMPONENTS_DATA_DIR` и build QML imports. `readelf`/`ldd`
подтвердили `$ORIGIN/../Core` и загрузку соседнего установленного Core. API inventory
перегенерирован после сверки и `--check` прошёл. Qt 6.11.2, GCC 16.2.0, Linux,
offscreen. CMake consumer нашёл Theme plugin в staging-prefix. Установленный
`kos-settings --smoke-test` и `--smoke-test-windows` загрузили `installed copy`;
повторная проверка страницы окон прошла при временно скрытом UI Kit build tree.
Исходный checkout оставался на диске, но журнал подтвердил выбор установленной
копии QML. Deploy в пользовательский Quickshell runtime и GUI-показ остаются.
