# PLASMA-RESTORE: Добавить возврат к обычной Plasma

- **Статус:** Готово
- **Обновлено:** 2026-10-27
- **Источник:** запрос пользователя «plasmatheme напиши скрипт возврата обычной плазма»; [PLASMA-DEFAULT](PLASMA-DEFAULT.md).
- **FT/UI:** `UI_SBEROS_PANEL_USSURI_1.1`; меняется способ запуска shell, не интерфейс панели.
- **Сценарии:** `03-01` (обычная панель Plasma), `02-02` (запуск приложений).
- **Зависимости:** пользовательская `plasma-plasmashell.service`, сохранённый профиль `plasma-org.kde.plasma.desktop-appletsrc`.
- **Неясности:** запрос трактуется как подготовка скрипта; переключение текущей сессии не запрашивалось.

## Критерии готовности

- [x] Удалять только известный drop-in SberOS, сохранив резервную копию.
- [x] Перезагружать конфигурацию systemd и штатный `plasmashell`; проверять его активность.
- [x] Поддержать предварительный просмотр и безопасный повторный запуск.
- [x] При ошибке перезапуска возвращать drop-in и пробовать восстановить прежний shell.
- [x] Описать запуск и проверить сценарии без изменения рабочей сессии.

## Результат и проверки

Добавлен `plasma-theme/restore-plasma.sh`. Он принимает `--dry-run`, отказывается
удалять изменённый или символьный drop-in, проверяет итоговый `ExecStart` перед
перезапуском и сохраняет копию в `~/.local/state/sberos-shell/plasma-restore/`.
При неудаче возвращает исходный drop-in. Установленные KPackage и профили Plasma
не удаляются.

Проверены `bash -n`, `git diff --check` и изолированная подмена `systemctl`:
предпросмотр, успешный возврат, повторный запуск, ошибка перезапуска и откат.
Живая служба не перезапускалась; графическая и функциональная проверка сценариев
`03-01` и `02-02` остаётся на момент фактического переключения пользователя.

## Следующий шаг

По запросу пользователя выполнить скрипт в текущем сеансе и проверить службу,
обычную панель и запуск приложений.
