# QML-STYLE-001: Отформатировать QML в UI Kit и Sirca Shell

- **Статус:** Готово
- **Обновлено:** 2026-10-23
- **Источник:** запрос пользователя от 2026-10-23 на форматирование QML в `ui-kit/` и `shell/`.
- **Требования FT/UI:** продуктовые FT/UI не затрагиваются; задача меняет только формат исходников.
- **Сценарии:** не применимо; поведение продукта не меняется.
- **Зависимости:** корневой `.qmlformat.ini`.

## Цель и границы

Применить Qt `qmlformat` к исходным `.qml` файлам в `ui-kit/` и `shell/`.
Каталоги `build/` и `_build/` исключаются; `refs/` не входит в эти исходные проекты.
Используется существующий корневой `.qmlformat.ini`: четыре пробела, переносы
строк `native` (Unix в текущем окружении),
без нормализации порядка свойств и без сортировки импортов.

## Критерии готовности

- [x] Все исходные QML файлы UI Kit и Sirca Shell проходят `qmlformat`.
- [x] Повторный запуск formatter не меняет результат.
- [x] Изменения не затрагивают поведение, API, зависимости или сборку.
- [x] Проверки и их ограничения записаны.

## Готовность по проектам

- UI Kit: исходные QML файлы `ui-kit/` отформатированы, сборка завершилась успешно.
- Sirca: исходные QML файлы `shell/` отформатированы, сборка завершилась успешно.
- NextKDE: `refs/NextKde/` не входит в задачу и не изменён.

## Результат

`ui-kit/` и `shell/` отформатированы Qt `qmlformat` версии 6.11.2 по корневому
`.qmlformat.ini`. Проверка идемпотентности прошла для 179 исходных QML файлов;
`git diff --check` прошёл. Сборки UI Kit и Sirca Shell завершились успешно.
`python3 ui-kit/tools/api_contract.py --check` требует ревью `docs/API-catalog.md`
и `docs/api-source-manifest.json`; файлы не перегенерировались, поскольку API-изменения
в рабочем дереве нужно отличить от форматирования. Тесты не запускались.

## Коммиты

Коммит не создан: в рабочем дереве уже были незавершённые изменения в тех же QML
файлах, поэтому их нельзя безопасно отделить от форматирования в отдельном коммите.
