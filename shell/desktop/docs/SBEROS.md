# Адаптация Desktop под SberOS UI Kit

Состояние: первый этап [DESKTOP-001](../../../docs/tasks/DESKTOP-001.md),
сценарии `09-02`, `09-01`, `09-06`. Исходный Glass Desktop сохранён вместе с
лицензиями. Документ описывает адаптер палитры; палитры установлены и частично проверены
по отдельному запросу пользователя: [отчёт](checks/2026-10-22/README.md).

## Первый этап

Отдельный `tools/gen_sber_theme.py` генерирует `SberOSLight.colors`,
`SberOSDark.colors`, CSS для GTK 3/4 в обеих темах и `manifest.json`.
Требуется только Python 3, дополнительные Python-пакеты не нужны.
Генератор не вызывает D-Bus, установщики, команды KDE, переключатели или сервисы.

Из корня рабочей области:

```sh
python3 shell/desktop/tools/gen_sber_theme.py --output /tmp/sber-desktop-check
python3 shell/desktop/tests/test_sber_theme.py -v
# Необязательная проверка установленными парсерами GTK, каждый в своём процессе:
timeout 15s python3 shell/desktop/tests/check_gtk_css.py 3 /tmp/sber-desktop-check
timeout 15s python3 shell/desktop/tests/check_gtk_css.py 4 /tmp/sber-desktop-check
```

`--resources PATH` задаёт каталог ресурсов другой проверяемой копии UI Kit;
по умолчанию используется `ui-kit/resources` этой рабочей области.
`--output` обязателен; генератор перезаписывает только свои семь файлов в нём.
Для проверки используйте отдельный каталог, а не пользовательский профиль.
Одинаковые ресурсы дают побайтно одинаковый результат; время и абсолютные пути
в файлы не записываются. Манифест содержит SHA-256 прочитанных источников,
карту семантических ролей, выбранный цвет текста на акценте и конфигурацию
Darkly: `Common.CornerRadius` следует `Theme.Sizes.BorderRadius.S` (сейчас 8),
прозрачность меню, панелей и Dolphin — 100%, `TransparentDolphinView=false`.
Эти настройки применяются только при использовании Qt Widgets style Darkly.

## Контракт адаптера

Потребитель QML продолжает использовать [API UI Kit](../../../ui-kit/docs/API.md).
Адаптер конфигурационных файлов читает `theme/sdds_os.json` и ссылки вида
`[os.osGreen.600]` из `theme/colors/`. Конвертация проверена по
`ui-kit/theme/theme_functions.h`: исходные hex-строки — `RRGGBB`/`RRGGBBAA`,
во время загрузки UI Kit переводит их в Qt `AARRGGBB`. Генератор читает исходный
формат и не применяет к нему правила формата Qt.

| Роль рабочего окружения | Токен `Theme.Palette` |
| --- | --- |
| Окно, заголовок | `Background.Default.Primary` |
| Рабочая область, поле ввода | `Background.Default.Secondary` |
| Боковая панель, карточка, popup | `Background.Default.Tertiary` |
| Кнопка / hover / pressed | `Surface.Default.TransparentSecondary` / `TransparentSecondaryHover` / `TransparentSecondaryActive` |
| Выделение / hover / pressed | `Surface.Default.Accent` / `AccentHover` / `AccentActive` |
| Текст / неактивный / disabled | `Text.Default.Primary` / `Secondary` / `Tertiary` |
| Ссылка | `Text.Default.Info` |
| Успех / предупреждение / ошибка | `Text.Default.Positive` / `Warning` / `Negative` |
| Граница / фокус | `Outline.Default.SolidSecondary` / `Accent` |
| Текст выделения | `Text.OnLight.Primary` либо `Text.OnDark.Primary` |
| Радиус Qt Widgets Darkly | `Theme.Sizes.BorderRadius.S` |

Названия `TransparentSecondary` не означают разрешения просвечивания рабочего
стола: в текущем UI Kit их значения непрозрачны. При появлении альфа-канала
у выбранного фона генерация завершается с ошибкой до записи результатов.
Полупрозрачный текст смешивается с конкретной поверхностью, RGB округляется
до ближайшего целого. Текст на акценте выбирается из двух токенов по наибольшему
минимальному контрасту на normal/hover/pressed. Это адаптация для ограниченных
палитр KDE/GTK, а не обещание достижения заданного порога доступности.

KDE получает отдельные группы Window/View/Button/Selection/Tooltip/Header и WM;
все экспортированные цвета — непрозрачные RGB. GTK получает именованные цвета
и общий для GTK 3/4 набор правил normal/hover/pressed/disabled/selection/focus.
Это базовый слой поверх темы toolkit: он не заменяет весь набор состояний,
виджетов и клиентских декораций. Радиусы, шрифты, размеры, тени, иконки,
параметры disabled KDE и глобальные эффекты пока не меняются. Это сохраняет
пользовательское масштабирование текста; соответствие типографике UI Kit
ещё предстоит реализовать и проверить.

## Карта исходного комплекта и потребителей

| Область | Текущее назначение / потребители | Действие |
| --- | --- | --- |
| `design/tokens.json`, `tools/tokens2css.py`, `design/mock/` | Палитра Glass и HTML-макеты | Сохранить как исходный референс. Новые палитры SberOS не зависят от этих токенов |
| `design/fonts/`, `design/wallpaper/`, `tools/make_default_wallpaper.py`, `wallpaper_variants.py` | Исходные ресурсы; генераторы обоев | Сохранить происхождение, лицензии и пользовательские обои; выбор фирменных ресурсов отложен |
| `tools/gen_kde.py`, `gen_gtk.py` | Glass-генераторы; вызываются apply-скриптами и `mode.sh` | Сохранить переходный путь; новый генератор SberOS изолирован от него |
| `tools/apply_kde.sh`, `apply_gtk.sh`, `apply_all.sh` | Применение Glass, резервные копии и откат; вызывает `shell/install.sh` | Не использовать для новых палитр. Следующий этап — отдельное применение и откат в тестовом профиле |
| `tools/mode.sh` | Команда `glass-mode`; оболочка вызывает её из Main, QuickSettings, QSAutoMode; установщик создаёт ссылку | Сохранить до согласованной миграции SHELL-001. Продолжает применять Glass, а не SberOS |
| `tools/palette.py` | Акцент из обоев; `mode.sh`, сравнение с Palette оболочки | Сохранить совместимость; произвольный акцент не включён в адаптер SberOS |
| `tools/folder_color.sh`, `folder_theme.py` | `glass-folder-color` в Settings.qml, Papirus | Сохранить необязательный старый интерфейс до миграции настроек |
| `qt/darkly-fork/`, `tools/install_qt.sh`, `use_decoration.sh`, `nest_test.sh` | Darkly Qt Widgets style и отдельная декорация; исторически установка через `shell/install.sh`, nested KWin | Darkly выбран как основа Qt Widgets, радиус по умолчанию сверен с UI Kit S и сборка проверена изолированно. Плагин не установлен в системный каталог; основу декораций окон выбираем отдельно |
| `third_party/adw-gtk3/` | GTK 3 база, используется `apply_gtk.sh` | Сохранить лицензию и старый путь; выбор GTK-базы SberOS отложен |
| `lock/`, `tools/install_lock.sh`, `lock_state.sh`, `make_lock_assets.sh` | Экран блокировки, синхронизация режима/обоев и KWin service drop-in | Сохранить до отдельного этапа; не менять аутентификацию и сессию ради палитры |
| `plasma/osd/` | Подмена OSD Plasma при собственном OSD оболочки | Рассмотреть исключение из базового оформления после проверки отсутствия дублирования OSD |
| `kwin/glasstranslucent/` | Принудительная прозрачность приложений | Не включать в оформление SberOS; пока сохранить исходник без включения/удаления |
| `apps/`, `tools/gen_spotify.py`, `install_spotify_widget.sh`, `spotify_cdp.py` | Необязательное оформление сторонних приложений, Spotify/CDP | Не включать в первый этап; сохранить старых потребителей и лицензии |
| `tools/ensure_session.sh` | Сервис `glass-desktop-ensure`, восстанавливает Glass при входе | Не использовать для SberOS: переустанавливает старое оформление. Заменять вместе с миграцией установщика |

Удаления на первом этапе нет: сохранённый файл не означает включение его
в целевой продукт. Darkly принят как Qt Widgets style; декорация окон, экран блокировки и GTK-база
рассматриваются отдельно. Наличие исходников само по себе не означает установку.

## Границы проверок и продолжение

Unit-проверки и нативные CSS-парсеры подтверждают формат, чтение токенов и
изоляцию файлов. Исходники Darkly собраны, плагин запущен только из временного
каталога в отдельном Wayland-окне, скриншоты просмотрены. Это подтверждает его
работу с палитрой UI Kit, но не установку в системный Qt-путь или работу
в существующих приложениях. Скриншоты до/после реальных KDE/GTK
окон, версии toolkit и окружение должны сопровождать следующий этап предпросмотра.
Ни генерация, ни эти тесты не меняют тему, размер текста, обои или панели.

Ручная установка палитр и откат проверены в текущей Wayland-сессии по прямому
запросу пользователя; итоговый режим — SberOSDark. Полноценного установщика
SberOS и синхронизации с настройками оболочки пока нет. Следующий этап:
визуальная проверка GTK 4/libadwaita, установка/переключение Darkly в системных
приложениях и выбор основы декораций. Код оболочки и UI Kit менять
совместно с владельцами параллельных SHELL-001/UIKIT-001, не поверх их работы.
