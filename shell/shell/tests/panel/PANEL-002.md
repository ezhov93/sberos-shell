# PANEL-002: меню Сбер

Дата: 2026-10-22. [Задача](../../../../docs/tasks/PANEL-002.md),
[правила](../../../../docs/rules/sber-menu.md), [ADR-0009](../../../../docs/adr/0009-smart-panel-scope.md).

## Изменение

Крайняя левая кнопка раскрывает вверх четыре иконки без постоянных подписей:
настройки shell, терминал, питание/сессия, сворачивание. Питание и контекст
терминала открываются справа. Меню существует в одном экземпляре, панель
удерживается видимой; внешние клики на всех экранах поглощаются по уровням.
Контекст терминала содержит KService desktop actions, затем закрепление.
Внутренние настройки shell не получают контекстное меню внешнего приложения.

В unified общий вызов launcher/Super направлен в меню Сбер; в split сохранён
прежний лаунчер. Кнопка Applications в области задач по-прежнему открывает лаунчер.
Раскрытие меню не сдвигает остальные зоны. Фоны и контролы используют UI Kit,
прозрачная часть окна остаётся только вне видимых блоков, blur не запрашивается.

## Окружение и результаты

Qt 6.11.2, GCC 16.2.0, Linux x86_64.

- Configure/build прошли; добавлены QML-компоненты и KF6 KIOGui для запуска
  desktop actions стандартным ApplicationLauncherJob.
- Offscreen/software: два виртуальных экрана по **1920×1080**, события мыши
  и клавиатуры QtTest/TestEvent. `--menu`: PASS, exit 0.
- Текущий KDE/KWin Wayland: один логический экран **1920×1200**, масштаб 2,
  физический 3840×2400. `--menu --wayland`: PASS, exit 0.
- Регрессия `--layout` (пять зон, обе темы, popup, split/unified): PASS, exit 0.
- API-контракт UI Kit, синтаксис Python runner и `git diff --check`: PASS.

В финальных журналах нет PANEL FAIL, ReferenceError, TypeError, циклов привязок
и ошибок присваивания. Изменения конфигурации выполнялись во временных XDG-каталогах.
Все тестовые процессы завершены; панели Plasma и глобальные сочетания не переключались.

Проверено:

- Четыре пункта, отсутствие начального выбора, Enter без выбора, Down/Tab/Up.
- Контекст по клавише Menu и ПКМ, без запуска приложения; возврат фокуса по Esc.
- Закрепление/открепление через контекст и обновление временной конфигурации,
  сохранение открытого основного меню. Исходные закрепления восстановлены.
- Повторная кнопка/внешний клик закрывают дочерний уровень без запуска пункта
  под ним; последовательные Esc закрывают дочернее, затем основное меню.
- Кнопка настроек открывает настоящее собственное окно Settings; терминал
  проверен как запрос запуска без создания процесса.
- Shutdown требует подтверждения; подтверждённый вызов с dryRun=true закрывает
  все уровни и только пишет журнал. Реальные питание, блокировка, сон и выход
  из сессии не выполнялись.
- Общий `Shell.toggleLauncher()` закрывает все уровни. На двух виртуальных экранах
  проверены внешний клик на другом экране, первый клик по другой кнопке (только
  закрытие дочернего), второй клик (перенос), повторное клавиатурное открытие на
  последнем активном экране. Один и тот же объект меню переиспользуется.
- Снимки двух тем просмотрены; режим основного сервиса этой проверкой не включался.

При проверке двух экранов исправлены цикл видимости catcher и привязка к экрану:
для выбора выхода используются данные ScreenSet и имена экранов, для обычных
Qt-окон учитываются virtualX/virtualY. Не следует приравнивать переопределённый
платформой Window.screen к целевому экрану панели.

## Ограничения

Ширины 1280/1440 отложены по ADR-0008. Два реальных монитора и hotplug не
проверены: виртуальные экраны проверяют маршрутизацию, но не поведение оборудования.
В Wayland захват grabToImage ранее не завершался; снимки получены offscreen.
Проверка одиночного физического Super после отпускания, удержания, автоповтора
и сочетаний с Super в основном сервисе ещё не выполнена. Код использует прежний
KGlobalAccel bare-modifier action, а не собственный перехват клавиатуры;
в тесте проверен его QML/D-Bus маршрут, не аппаратный ввод.

Реальный запуск терминала/его desktop actions и переход фокуса в новое приложение
не выполнялись. Питание использует существующие пять действий и подтверждения;
отсутствующая внешняя power-menu спецификация, действия с обновлением и новые
политики доступности не реализуются этой задачей.

Известные предупреждения тестовой среды (ClickTracker, fake input, глобальные
сочетания, Glass, занятый notification server) не выдаются за исправленные.

Области сценариев: `02-02`, `04-07`, `09-24`; точки входа `10-01`, `10-05`,
`10-07`, `10-09` проверены только до безопасного запроса/dry-run. Полная приёмка
системных сценариев сна, выключения и блокировки не заявляется.

## Воспроизведение

```sh
cmake -S shell/shell -B /tmp/sberos-shell-build -DCMAKE_BUILD_TYPE=Debug
cmake --build /tmp/sberos-shell-build -j 4
python3 shell/shell/tests/run-panel-smoke.py --menu --output /tmp/sber-panel002-check
python3 shell/shell/tests/run-panel-smoke.py --menu --wayland --output /tmp/sber-panel002-wayland
python3 shell/shell/tests/run-panel-smoke.py --layout --output /tmp/sber-panel002-layout
python3 ui-kit/tools/api_contract.py --check
```

Для --menu нужен QML-модуль QtTest. Runner создаёт отдельную D-Bus-сессию
для offscreen и ограничивает запуск 25 секундами; Wayland использует текущую
шину и временную конфигурацию. Wayland-команда кратковременно показывает меню
и окно настроек, не берёт глобальные сочетания и ничего не выключает.
