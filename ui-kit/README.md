# SberOS UI Kit

Общий UI Kit для собственной оболочки SberOS и приложений её экосистемы.
Объединяет компоненты QML/C++ для Qt 6, тему, иконки и демонстрационную
галерею. Собирается одной командой CMake и запускается без системной установки.

## Назначение и границы

`ui-kit` — общая основа интерфейса оболочки из `shell/` и приложений:
единые компоненты, цвета, типографика, размеры, иконки и визуальные состояния.
Общие элементы интерфейса развиваются здесь и переиспользуются оболочкой
и приложениями. Логика рабочего стола остаётся в оболочке, предметная логика
приложений — в соответствующих приложениях.

Это целевое назначение проекта. Текущая галерея демонстрирует компоненты;
подключение UI Kit к оболочке и приложениям выполняется отдельно и само
по себе не следует из наличия библиотеки.

По [ADR-0006](../docs/adr/0006-settings-ui-kit.md) принято перевести
собственное окно настроек оболочки на UI Kit. Общие элементы развиваются
здесь, привязки к конфигурации и сервисам остаются в `shell/`.
[Правила миграции](../docs/rules/settings-ui-kit.md) задают проверки
совместимости и интерфейса. Окно настроек использует UI Kit; библиотека
собирается отдельно и подключается параметром `SBER_QML_IMPORT_PATH` сборки оболочки.
Изолированные проверки выполнены, проверка в Wayland-сессии предстоит.

## API для потребителей

При разработке оболочки и приложений используйте [API-контракт](docs/API.md)
как основной справочник. Он описывает подключение, тему, основные компоненты,
события и ограничения текущей реализации. Полный статический перечень
собственных объявлений — в [каталоге](docs/API-catalog.md), пути цветов,
размеров и шрифтов — в [каталоге токенов](docs/API-tokens.md).

Контракт позволяет использовать описанное API без повторного чтения реализации.
При пробеле в документации или ошибке уточните поведение по нужному исходнику
и обновите контракт. При изменении библиотеки обновляйте документацию вместе с кодом.

```sh
python3 ui-kit/tools/api_contract.py --check
```

Команда проверяет актуальность каталогов и отпечатка исходников без запуска Qt.
Порядок обновления и ограничения проверки описаны в контракте.

## Структура

- `core/`, `controls/`, `theme/`, `utils/`, `widgets/` — исходники модулей
  `Sber.Core`, `Sber.Controls`, `Sber.Theme`, `Sber.Utils`, `Sber.Widgets`.
- `resources/theme/` — цвета, размеры и настройки шрифтов из `sberos-theme`.
- `resources/icons/` — SVG из `sberos-app-icons`.
- `examples/gallery/` — интерактивная галерея компонентов.
- `tests/` — тест загрузки плагинов Qt Test/CTest; `po/` — переводы.
- `upstream/` — исходные README, лицензии, история изменений и материалы
  пакетирования темы, иконок и метапакета. Эти материалы сохранены для
  происхождения ресурсов; их старые install-скрипты и пути не являются
  инструкцией сборки объединённого проекта.
- `LICENSES/`, `debian/`, `build_scripts/` — лицензии и исходные материалы
  библиотеки компонентов. Старое Debian-пакетирование ещё не адаптировано
  к объединённому проекту.

## Сборка и запуск

Нужны CMake, компилятор C++20 (Clang или GCC), Qt 6 Core/Gui/Widgets/Qml/Quick/
Svg/Xml/DBus/LinguistTools, pkg-config и GLib. Для запуска нужны QML-модули
Qt Quick, Controls, Templates, Layouts, Window, Shapes, Effects и
Qt5Compat.GraphicalEffects. Для штатных тестов дополнительно нужен модуль Qt Test.

Из корня рабочей области:

```sh
cmake -S ui-kit -B ui-kit/_build -DBUILD_WITH_CTEST=OFF
cmake --build ui-kit/_build -j 4
./ui-kit/_build/examples/gallery/sber-components-gallery
```

С модулем Qt Test:

```sh
cmake -S ui-kit -B ui-kit/_build -DBUILD_WITH_CTEST=ON
cmake --build ui-kit/_build -j 4
ctest --test-dir ui-kit/_build --output-on-failure
```

`BUILD_EXAMPLES` по умолчанию включён. Результаты сборки, QML-модули и
сгенерированные CMake-конфиги находятся в каталоге сборки; каталог исходников
не используется для новых результатов сборки. `THEME_RESOURCES_PATH` по
умолчанию указывает на встроенный `resources/`, его можно переопределить
через `-DTHEME_RESOURCES_PATH=/путь/к/ресурсам`.

Установить библиотеку в системный или staging-префикс можно командой
`cmake --install ui-kit/_build --prefix /путь/к/префиксу`. QML-модули размещаются
в Qt QML-подкаталоге относительно Qt-префикса, а CMake package-конфиги вычисляют
пути библиотек и заголовков относительно префикса установки. Для запуска из
нестандартного префикса добавьте его QML-каталог в `QML_IMPORT_PATH` и задайте
`SBER_COMPONENTS_DATA_DIR=<префикс>/share/SberComponents`; установленным плагинам
не нужен build-каталог для поиска соседнего `Sber.Core`.

[Галерея: запуск и скриншоты](examples/gallery/README.md).

## Происхождение

Проект объединяет исходные снимки `sberos-qml-components`, `sberos-theme`,
`sberos-app-icons` и материалы метапакета `sberos-components`, ранее находившиеся
в `external/`. Имена QML-модулей и авторские лицензии сохранены.

Проверочная конфигурация: Qt 6.11.2, GCC 16.2.0, Linux, программный рендеринг
Qt Quick через `offscreen`, без подключения к сеансу KDE. Фирменные шрифты
устанавливаются отдельно; Qt использует замену, если они отсутствуют.
